# [SC-036] Add Negotiate (Kerberos) proxy auth mode to setup-proxy

**Status**: Open
**Priority**: High
**Component**: `lib/wsl/proxy.ps1`, `lib/wsl/scripts/setup-proxy.sh`, `docs/wsl-manager.md`
**Related**: SC-007 (setup-proxy - Basic auth)

**Summary**:
As a developer in a corporate environment with a Kerberos-only proxy (no NTLM), I want `wsl-manager setup-proxy` to offer a Negotiate auth mode so that my credentials are never stored in environment variables and AI coding agents (Copilot, Claude) cannot read them.

**Description**:
The current `setup-proxy` (SC-007) supports Basic authentication: credentials are embedded in the proxy URL and exported as environment variables (`http_proxy=http://user:pass@proxy:port`). This means every process in the shell session — including AI coding agents such as GitHub Copilot and Claude — can read those credentials via `$env:HTTP_PROXY` or `/proc/*/environ`.

The company proxy supports Negotiate (Kerberos/SPNEGO) authentication. The user has manually verified that `krb5-user` + `kinit` + `curl --proxy-negotiate` work. However, most tools in WSL (`apt`, Docker daemon, Podman, etc.) do not support SPNEGO proxy authentication themselves.

The solution: install **px (Px Proxy)** as a local authenticating proxy inside WSL. px uses the system Kerberos ticket (obtained via `kinit`) to authenticate to the company proxy via SPNEGO on behalf of all tools. All tools simply point to `http://localhost:<port>` — no credentials anywhere in env vars.

**Workflow (Negotiate mode)**:
1. User runs `wsl-manager setup-proxy <distro>` (or selects from menu) and picks auth method
2. **Basic** (existing behavior): prompt for credentials, embed in proxy URL - unchanged
3. **Negotiate** (new) - four phases:

   **Phase 1 - Bootstrap (temporary Basic auth)**:
   Installing Kerberos and px requires apt/pip to work, which requires a working proxy.
   This is a chicken-and-egg problem: to set up the Negotiate proxy, we first need proxy
   access to download packages. Solution: temporarily use Basic auth for the bootstrap.
   - Auto-detect proxy URL (existing PAC/registry logic)
   - Prompt for Basic auth credentials (temporary, used only for package installation)
   - Configure apt proxy with `user:pass@proxy:port` (temporary)
   - `apt install krb5-user pipx`
   - `HTTP_PROXY=user:pass@proxy pipx install px-proxy` + `pipx ensurepath`

   **Phase 2 - Kerberos + px configuration**:
   - Prompt for Kerberos realm (e.g., `CORP.COMPANY.COM`) and KDC hostname
   - Write `/etc/krb5.conf` with realm + KDC
   - Write `~/.config/px/px.ini` pointing to the company proxy (auth = NEGOTIATE, no credentials)
   - Run `kinit` interactively (user enters Kerberos password in the terminal)

   **Phase 3 - Activate and verify px**:
   - Start px
   - Run `px --test` to verify the proxy works with the Kerberos ticket

   **Phase 4 - Switch to localhost and cleanup**:
   - Reconfigure all targets (`.profile`, apt, Docker, Podman) to `http://localhost:3128`
   - Add px auto-start + kinit reminder to `.bashrc` managed block
   - Basic auth credentials are gone: overwritten by localhost URLs, never persisted

**Security properties of Negotiate mode**:
- No credentials in env vars or config files
- Kerberos ticket lives in the kernel keyring or `/tmp/krb5cc_<uid>`, inaccessible to other processes
- AI coding agents see `HTTP_PROXY=http://localhost:3128` — useless without the ticket

**Scope Decisions**:
- **Bootstrap via Basic auth**: Negotiate mode has a chicken-and-egg problem: installing `krb5-user` and `px` requires apt/pip, which needs a working proxy - but the Negotiate proxy (px) is what we're trying to install. Solution: temporarily configure Basic auth (`user:pass@proxy:port`) for the package installation phase only; then switch everything to `http://localhost:3128` once px is running. Credentials are never persisted - they're overwritten by localhost URLs in Phase 4.
- **`kinit` runs during setup**: Rather than deferring `kinit` to a post-setup manual step, the setup runs `kinit` interactively so the user enters their Kerberos password in the terminal. This allows `px --test` to verify the full chain immediately.
- **cntlm is out**: cntlm supports NTLM/NTLMv2 only, not Kerberos/SPNEGO. The company proxy does not support NTLM.
- **px chosen**: px (https://github.com/genotrance/px) supports Negotiate/Kerberos on Linux via libkrb5/GSSAPI. It is the lightest-weight option that works with a Kerberos-only upstream proxy. **Verified**: `px --test --auth=NEGOTIATE` passes (GET and PATCH succeed); without `--auth=NEGOTIATE` px defaults to NTLM which fails with a 503.
- **`auth = NEGOTIATE` is mandatory**: must be set in `px.ini` explicitly — px's default auth mode (NTLM) will not work with a Kerberos-only proxy.
- **krb5.conf**: user provides realm and KDC manually — no DNS auto-discovery, to keep setup explicit and auditable.
- **px port**: default `3128`; document how to override if it conflicts. In `px.ini`, use `port` for the port number and `listen` for the bind IP (`127.0.0.1`). Using `listen = 3128` (a number) causes `[Errno 99] Cannot assign requested address`.
- **Auth method choice**: extend the existing `Install-WslProxy` function with an auth method prompt — no separate action needed.
- **Basic mode unchanged**: existing behavior (embed credentials in URL, export in env vars) stays as-is for proxies that require it.
- **px auto-start**: add a px startup block to `.bashrc` managed section; document that `kinit` must be run first to get a ticket.

**Technical Notes**:
- px install in WSL (Ubuntu): use `pipx` (not `pip3` — Ubuntu 24.04+ enforces PEP 668 which blocks system-level pip installs):
  ```bash
  sudo apt install pipx
  pipx install px-proxy
  pipx ensurepath   # adds ~/.local/bin to PATH if not already present
  ```
  `px` binary lands in `~/.local/bin/px`. The `.bashrc` auto-start block relies on `~/.local/bin` being in `$PATH`; `pipx ensurepath` ensures this.
- Minimal `/etc/krb5.conf`:
  ```ini
  [libdefaults]
      default_realm = CORP.COMPANY.COM

  [realms]
      CORP.COMPANY.COM = {
          kdc = kdc.company.com
          admin_server = kdc.company.com
      }

  [domain_realm]
      .company.com = CORP.COMPANY.COM
      company.com = CORP.COMPANY.COM
  ```
- Minimal `~/.config/px/px.ini` (**`auth = NEGOTIATE` is required** — without it, px defaults to NTLM which fails with a Kerberos-only proxy):
  ```ini
  [proxy]
  server = proxy.company.com:8080
  port = 3128
  listen = 127.0.0.1
  auth = NEGOTIATE
  ```
  Note: `port` is the port number to listen on; `listen` is the IP address to bind to (must be `127.0.0.1`, not the port — using a port number here causes `[Errno 99] Cannot assign requested address`).
- `.bashrc` managed block (Negotiate mode):
  ```bash
  # BEGIN wsl-manager proxy
  # Run 'kinit' first to authenticate with Kerberos before using the proxy
  export HTTPS_PROXY="http://localhost:3128"
  export HTTP_PROXY="http://localhost:3128"
  export https_proxy="http://localhost:3128"
  export http_proxy="http://localhost:3128"
  export NO_PROXY="localhost,127.0.0.1"
  export no_proxy="localhost,127.0.0.1"
  # Start px local proxy (requires valid Kerberos ticket via kinit)
  pgrep -x px > /dev/null || nohup ~/.local/bin/px > /dev/null 2>&1 &
  # END wsl-manager proxy
  ```
