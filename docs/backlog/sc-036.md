# [SC-036] Add Negotiate (Kerberos) proxy auth mode to setup-proxy

**Status**: In Progress
**Priority**: High
**Component**: `lib/wsl/proxy.ps1`, `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/scripts/setup-proxy-negotiate.sh` (new), `docs/wsl-manager.md`
**Related**: [SC-007](sc-007.md) (setup-proxy — Basic auth)

**Summary**:
As a developer in a corporate environment with a Kerberos-only proxy (no NTLM), I want `wsl-manager setup-proxy` to offer a Negotiate auth mode so that my credentials are never stored in environment variables and AI coding agents (Copilot, Claude) cannot read them.

**Description**:
SC-007's Basic mode embeds credentials in the proxy URL and exports them as `HTTP_PROXY=http://user:pass@proxy:port`. Every process in the shell — including AI coding agents — can read those creds via `/proc/*/environ`.

The company proxy supports Negotiate (Kerberos/SPNEGO). The solution is to install **px (Px Proxy)** as a local authenticating proxy inside WSL. px uses the system Kerberos ticket (obtained via `kinit`) to authenticate to the upstream proxy via SPNEGO on behalf of all tools. All tools simply point to `http://localhost:3128` — no credentials anywhere in env vars.

The Negotiate workflow is four phases (bootstrap → configure Kerberos/px → activate → switch targets to localhost). Basic mode is unchanged.

### Stories

This epic is broken into five independently UAT-able stories:

1. [SC-036a](sc-036a.md) — Auth-method prompt + mode marker file; Negotiate path stubbed
2. [SC-036b](sc-036b.md) — Phase 1: bootstrap install of `krb5-user` and `px-proxy` (creds in config files only, never exported)
3. [SC-036c](sc-036c.md) — Phases 2–3: write `krb5.conf` + `px.ini`, run `kinit` interactively, start px, verify with `px --test`
4. [SC-036d](sc-036d.md) — Phase 4: switch `.profile`/apt/Docker/Podman to `http://localhost:3128`; add `.bashrc` px auto-start block with `klist -s` guard
5. [SC-036e](sc-036e.md) — Mode-aware `--remove` teardown; update `docs/wsl-manager.md`

SC-036a is the foundation. b/c/d must proceed in order. SC-036e depends on SC-036d.

**Scope Decisions** (cross-cutting; stories inherit these):
- **Bootstrap via temporary Basic auth, creds in config files only**: Phase 1 writes Basic-auth creds to `apt.conf.d/99proxy` and a temp `~/.config/pip/pip.conf`; never exported to any process environment. Preserves the Negotiate threat model (no creds readable via `/proc/*/environ`) even during install. Detail lives in SC-036b.
- **Sibling script, not branching**: Negotiate logic lives in a new `setup-proxy-negotiate.sh`. The existing `setup-proxy.sh` writes config files only; adding package installs + long-lived service management to the same script would couple three different kinds of work. Detail lives in SC-036a.
- **Mode marker file `/etc/wsl-manager/proxy-mode`** (`basic` | `negotiate-bootstrap` | `negotiate`): written at the appropriate phase so that `--remove` (SC-036e) can dispatch the correct teardown. Missing marker falls back to Basic teardown (backwards-compatible).
- **Failure policy — no half-migration**: if Phase 2/3 fails (kinit or `px --test`), leave `.profile`/apt in the Phase-1 Basic-auth state and exit non-zero. User keeps a working proxy; no tool ends up pointing at a non-working localhost. Detail lives in SC-036c.
- **`/etc/krb5.conf` is system-wide**: teardown does **not** delete it — the user may rely on Kerberos for SSH/other services. Detail lives in SC-036e.
- **`kinit` runs during setup**: the user enters their Kerberos password once during SC-036c so `px --test` can verify end-to-end immediately.
- **cntlm is out** (NTLM-only, upstream doesn't support NTLM). **px chosen** because it supports Negotiate/Kerberos via libkrb5/GSSAPI; `auth = NEGOTIATE` is mandatory in `px.ini` (default NTLM fails against a Kerberos-only upstream).
- **`pipx`, not `pip3`**: Ubuntu 24.04+ enforces PEP 668.

**Technical Notes**:
- **Minimal `/etc/krb5.conf`** (written in SC-036c):
  ```ini
  [libdefaults]
      default_realm = CORP.COMPANY.COM
  [realms]
      CORP.COMPANY.COM = {
          kdc = kdc.company.com
          admin_server = kdc.company.com
      }
  [domain_realm]
      .company.com = CORP.COMPANY.COM
      company.com = CORP.COMPANY.COM
  ```
- **Minimal `~/.config/px/px.ini`** (written in SC-036c — `auth = NEGOTIATE` is required; without it px defaults to NTLM and 503s against a Kerberos-only upstream; `listen` is an IP, not a port):
  ```ini
  [proxy]
  server = proxy.company.com:8080
  port = 3128
  listen = 127.0.0.1
  auth = NEGOTIATE
  ```
- **Phase 4 managed blocks** (added in SC-036d):
  - `.profile` block (env vars — same file and marker as Basic mode):
    ```bash
    # BEGIN wsl-manager proxy
    export HTTPS_PROXY="http://localhost:3128"
    export HTTP_PROXY="http://localhost:3128"
    export https_proxy="http://localhost:3128"
    export http_proxy="http://localhost:3128"
    export NO_PROXY="localhost,127.0.0.1"
    export no_proxy="localhost,127.0.0.1"
    # END wsl-manager proxy
    ```
  - `.bashrc` block (px auto-start — interactive shells only; `klist -s` guard avoids silent breakage when the ticket expires):
    ```bash
    # BEGIN wsl-manager proxy
    # Start px local proxy — requires a valid Kerberos ticket
    if klist -s 2>/dev/null; then
        pgrep -x px > /dev/null || nohup ~/.local/bin/px > /dev/null 2>&1 &
    else
        echo "wsl-manager: run 'kinit' to authenticate with Kerberos before using the proxy"
    fi
    # END wsl-manager proxy
    ```

**Security properties of Negotiate mode (end state)**:
- No credentials in env vars or config files
- Kerberos ticket lives in the kernel keyring or `/tmp/krb5cc_<uid>`, inaccessible to other processes
- AI coding agents see `HTTP_PROXY=http://localhost:3128` — useless without the ticket
