# [SC-066a] wsl-manager applies the dev-stack role to a distribution

**Status**: In Progress
**Priority**: Medium
**Component**: `lib/wsl/commands.ps1`, `lib/wsl/docker.ps1`, `lib/wsl/podman.ps1`, `lib/wsl/devpod.ps1`, `lib/wsl/scripts/`, `lib/wsl/ansible/`, `lib/wsl/manager.docker.Integration.Tests.ps1`, `lib/wsl/manager.podman.Integration.Tests.ps1`, `bin/release/paths.txt`, `docs/wsl-manager.md`

**Summary**:
As a developer, I want one wsl-manager command that applies the `dev-stack` role to a distribution, so that a WSL distribution and my DevVM get their tools from one definition.

**Description**:
The hand-off part of [SC-066](sc-066.md). Today `setup-docker`, `setup-podman` and `setup-devpod` each run a shell script of their own (`install-docker.sh`, `install-podman.sh`, `install-devpod.sh`). The role `xxthunder/ansible-role-dev-stack` installs the same tools, and since v1.7.0 it also installs rootless Podman (`dev_stack_container_runtime: podman`, with `podman-docker`, `slirp4netns` and `uidmap`).

The new command runs after `setup-ca` and `setup-proxy`, because apt needs the corporate CA and the proxy before the first package. It installs Debian's `ansible-core` and `git` with apt, installs the role from `requirements.yml` and runs the playbook against `localhost`. wsl-manager reads the playbook from `/mnt/c`, the same way `Invoke-WslScript` runs every script today (`lib/wsl/exec.ps1`).

**Scope Decisions**:
- **One command replaces three** (decided 2026-11-27): `setup-dev-stack` with the runtime as a parameter, `podman` by default, `docker` as the other value. `setup-docker`, `setup-podman` and `setup-devpod` go away with their shell scripts; the repository builds no fallback path (AGENTS.md, "No Speculative Alternatives").
- **Ansible from apt** (decided 2026-11-27): Debian's `ansible-core` package, with `git` for the role's clone. `uvx` is not an option: the role installs uv, so uv is not there before the role runs. The role needs ansible-core 2.15 or later (its `meta/main.yml`).
- **The playbook and `requirements.yml` live in `lib/wsl/ansible/`** (decided 2026-11-27), next to `lib/wsl/scripts/`, where the shell scripts they replace live today.
- **The playbook comes from `/mnt/c`** (decided 2026-11-27), as every script does today. [SC-066b](sc-066b.md) decides what happens when `automount` is off.
- **The role is a git clone of tag v1.8.0** (decided 2026-11-27): `requirements.yml` names the repository with `scm: git` and `version: v1.8.0`. A later release is a version bump there.
- **Role variables** follow the values in SC-066: `dev_stack_container_runtime` from the parameter; `dev_stack_install_devpod`, `dev_stack_install_uv`, `dev_stack_install_gh` and `dev_stack_install_zsh` on; `dev_stack_ssh_agent` and `dev_stack_disable_password_auth` off; `dev_stack_install_claude_code` a switch of the command; `dev_stack_user` the distribution's default user.
- **wsl.conf keeps only what Podman needs from WSL** (decided 2026-11-27): `systemd = true` and the boot command `mount --make-rshared /`. The Podman prerequisites no longer write `interop` and `automount`; rootless Podman runs no Windows program. The UAT confirms this.
- **No `sudo` password** (decided 2026-11-27, replaces the `-K` decision of SC-066): `setup-user` already gives the user passwordless sudo (`lib/wsl/user.ps1`), and every install script runs plain `sudo`. The playbook runs with `become` and without `-K`, so the CI integration test does not wait at a prompt.
- **The runtime check stays in wsl-manager** (decided 2026-11-27): it refuses Podman on a distribution with Docker, and the other way round, and stops with a message before Ansible runs. The role is not asked to remove a runtime.
- **One integration test replaces two** (decided 2026-11-27): `manager.docker.Integration.Tests.ps1` and `manager.podman.Integration.Tests.ps1` become one test that runs the command with Podman. It runs in CI; integration tests do not run from WSL.

**Acceptance Criteria**:

- [ ] `setup-dev-stack` stops with a message when the distribution has the other container runtime
- [ ] A fresh distribution with CA and proxy gets Podman and DevPod, and a DevPod workspace builds and runs in it
- [ ] The same run installs uv, gh and zsh with oh-my-zsh, and Claude Code when switched on
- [ ] A second run of the command changes nothing (`changed=0` in the play recap)
- [ ] `setup-docker`, `setup-podman`, `setup-devpod`, `install-docker.sh`, `install-podman.sh` and `install-devpod.sh` are gone
- [ ] The Podman prerequisites write only `systemd` and the boot command to `wsl.conf`
- [ ] One integration test runs the command with Podman, and CI is green
- [ ] `bin/release/paths.txt` lists the playbook and `requirements.yml`
- [ ] `docs/wsl-manager.md` describes the new DevContainer setup steps
