# [SC-073i] Installer and update requirements

**Status**: Open
**Priority**: Medium
**Component**: `docs/requirements/install.md` (new), `docs/traceability/install.md` (new), `bin/install.ps1`, `bin/update.bat`, `links/` and their tests, `docs/index.md`
**Depends on**: [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want the behaviour of the installer and the update written down as requirement needs, traced to their code and tests, so that what `docs/index.md` promises is checked against what `install.ps1` does.

**Description**:
`docs/index.md` documents the installation (`irm …/install.ps1 | iex`, which installs Scoop, pwsh and the launcher), the shortcuts in `links/`, the update through `update.bat` or a second run of the installer, and its troubleshooting. `install.ps1` runs under Windows PowerShell 5.1.

**Scope Decisions**:
- **Requirements first, ubCode when it is ready** (author, 2026-11-14): this item does not wait for the rest of px-proxy (SC-073a, SC-073b, SC-073e, SC-073f). The only thing that waits is ubCode, which reads no PowerShell before its release with useblocks/ubcode#4750; the Sphinx build traces the markers with the codelinks pin of the day, and the ubCode comparison stays with [SC-073a](sc-073a.md). The pattern SC-073c settled (requirements by capability, markers on the functions and `It`s that implement and test them, ADRs that constrain them) is the one to copy.
- **Requirements are drafted by prompt and approved before anything is written**, as in [SC-073c](sc-073c.md): from what is true now, the code, its tests and the documentation; the Done items that touched the tool are hints, not a source. Behaviour that cannot be determined is listed in this item, not guessed.
- **Markers for its own requirements only**, as in SC-073c: the functions that implement a requirement and the `It`s that test it; the rest of the tool's functions wait for the check for unmarked functions in [SC-073e](sc-073e.md).
- **After SC-086** (the agent's call, not discussed): [SC-086](sc-086.md) replaces Keypirinha with PowerToys Command Palette on Alt+Space, and its pull request is open. Requirements on the launcher are written against what SC-086 leaves, so this item starts after it is merged.
- **Manual steps are no requirements** (the agent's call, not discussed): the uninstallation in `docs/index.md` is a list of commands for the user, not behaviour of a shortcuts tool.

**Acceptance Criteria**:
- [ ] `docs/requirements/install.md` states the installer's current behaviour as requirement needs, ordered by capability, approved by the author
- [ ] Every requirement is implemented and tested: a codelinks marker on a function and on a Pester `It` traces to it, and the documentation builds with Sphinx `-W`
- [ ] The ADRs that constrain the installer link the requirements they constrain
- [ ] The installer's documentation links its requirements and traces page, as px-proxy's runbook does
