# [SC-061] setup-proxy must not overwrite or delete apt, Docker and Podman files it does not own

**Status**: Open
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/proxy.ps1`, `docs/wsl-manager.md`
**Related**: [ADR 0002](../architecture/adr/0002-wsl-manager-changes-only-what-it-marked.md) (wsl-manager changes only what it marked), [SC-043](sc-043.md) (proxy env targets), [SC-036e](sc-036e.md) (mode-aware teardown)

**Summary**:
As a developer who keeps my own apt, Docker or Podman settings in a WSL distribution, I want `setup-proxy` to change only its proxy settings in those places, so that a re-run or Remove does not delete my registry logins or other configuration.

**Description**:
`setup-proxy` writes three client configurations as whole files and deletes them in Remove mode:

- `/etc/apt/apt.conf.d/99proxy` is written with `tee` and deleted on Remove. The name is generic, so an apt proxy file of the same name from the corporate IT or an image is overwritten or deleted.
- `~/.docker/config.json` is written with `cat >` and holds only `proxies.default`; Remove deletes it. Everything else in the file is lost on every run, including `auths` and `credsStore` from `docker login`.
- `~/.config/containers/containers.conf` is written with `cat >` and holds only `[engine] env`; Remove deletes it. Any other Podman setting in the file is lost.

This contradicts ADR 0002. The shell targets of `setup-proxy` already follow it: `/etc/profile.d/wsl-manager-proxy.sh` is its own file, and `/etc/zsh/zshenv` gets a marked block.

Found on 2026-09-28 while writing ADR 0002.

**Scope Decisions**:
- **Follow ADR 0002 for all three targets**: an own file with the `wsl-manager-` prefix where the tool reads a drop-in directory, otherwise only the proxy settings inside the shared file.
- **Existing distributions keep working**: a distribution set up by the current `setup-proxy` is migrated on the next run, and Remove still cleans up the old targets, without harming content `setup-proxy` did not write.
- **Not in scope**: the shell targets (`profile.d`, `zshenv`), which already follow ADR 0002.

**Open Questions**:
- **apt**: an own file such as `/etc/apt/apt.conf.d/99wsl-manager-proxy`. How is an old `99proxy` recognised as ours during migration: by its exact content?
- **Docker**: JSON has no comments, so a marked block is impossible. Merge only the `proxies` key: with which tool, given that `jq` and `python3` are not guaranteed in a fresh distribution? Or build the file on the Windows side in PowerShell and hand it over?
- **Podman**: does the Podman version in the supported distributions read `~/.config/containers/containers.conf.d/`? If yes, an own `wsl-manager-proxy.conf` there; if not, how to edit `[engine] env` inside a user's `containers.conf` without breaking its TOML?

**Acceptance Criteria**:
- [ ] Open Questions answered and recorded as Scope Decisions
- [ ] A re-run of `setup-proxy` on a distribution whose `~/.docker/config.json` holds `auths` or `credsStore` keeps them; only the proxy settings change
- [ ] Remove takes out only the proxy settings from the Docker and Podman configuration and leaves every other setting in place
- [ ] The apt proxy settings live in a file `setup-proxy` owns; an apt file it did not write is never overwritten or deleted
- [ ] A distribution set up by the current `setup-proxy` is migrated on the next run, and Remove on such a distribution still removes its old proxy settings
- [ ] Unit and integration tests cover foreign content surviving a re-run and a Remove, for all three targets
- [ ] The **Setup proxy (corporate)** section in `docs/wsl-manager.md` lists the targets as they are after the change
