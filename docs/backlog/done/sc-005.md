# [SC-005] ✅ COMPLETED - Move argument validation from Invoke-WslManager switch into action functions

**Status**: Completed (2026-03-07)
**Priority**: Medium
**Component**: `tools/pslib/wsl/lib/commands.ps1`

**Summary**:
As a WSL manager user, I want action commands to prompt me for missing arguments so that I don't have to remember the exact CLI syntax to use a command.

**Description**:
The `Invoke-WslManager` switch block inconsistently handles missing arguments like `$Name`. Some commands pass arguments through and let the action function prompt (e.g., `remove`, `update`), some branch to separate `*Interactive` functions (e.g., `setup-docker`, `setup-podman`, `setup-proxy`, `setup-user`), and one hard-fails with `exit 1` (e.g., `repair-interop`). Each action function should own its argument validation: accept what's given, prompt for what's missing. This eliminates the `IsNullOrWhiteSpace` checks in the switch, removes the need for separate `*Interactive` wrapper functions, and makes every command usable without arguments.

**Current inconsistencies** in `Invoke-WslManager` switch:
- `remove`, `update`, `clone` — pass `$Name` through; action functions prompt if missing
- `setup-docker`, `setup-podman`, `setup-proxy` — check `$Name` in switch, branch to `*Interactive` vs non-Interactive function
- `setup-user` — dispatches directly, but `Invoke-SetupUser` has `DistroName` as `[Mandatory]`, so empty `$Name` fails validation; interactive menu uses `Invoke-SetupUserInteractive` to prompt first
- `repair-interop` — checks `$Name`, hard-fails with `exit 1` if missing; additionally `Invoke-RepairInterop` is undefined
- `terminate` — checks `$Name`, branches to `Invoke-TerminateDistro` with or without `-Name` (redundant since the function already handles both cases)

**Scope decisions**:
- Each action function checks its own required arguments and prompts via `Read-Host` when missing
- `Invoke-WslManager` switch becomes a simple pass-through dispatcher — no `IsNullOrWhiteSpace` checks
- Separate `*Interactive` wrapper functions are merged into their non-Interactive counterparts:
  - `Invoke-SetupDockerInteractive` → `Invoke-SetupDocker`
  - `Invoke-SetupPodmanInteractive` → `Invoke-SetupPodman`
  - `Invoke-SetupProxyInteractive` → `Invoke-SetupProxy`
  - `Invoke-SetupUserInteractive` → `Invoke-SetupUser`
- `repair-interop` prompts for distro name instead of hard-failing
- `Invoke-RepairInterop` must be created (currently undefined) with proper prompting support
- The interactive menu (`Show-InteractiveMenu`) calls the merged functions directly
