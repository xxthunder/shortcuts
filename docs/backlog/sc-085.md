# [SC-085] Keypirinha hint test passes on a UNC repository path

**Status**: In Progress
**Priority**: Medium
**Component**: `bin/keypirinha-profile.Tests.ps1`

**Summary**:
As a developer who keeps the checkout in WSL and runs the tests from Windows, I want `bin/keypirinha-profile.Tests.ps1` to pass when the repository sits on a UNC path, so that a green local run means the same as a green CI run.

**Description**:
With the repository at a UNC path such as `\\wsl.localhost\deb-dev\home\wsluser\dev\xxthunder\shortcuts`, two tests fail: "Should name the profile hotkey in the catalog-refresh hint of <file>" for `lib/install/install-npm-global.ps1` and `tools/claude-code/install-claude-code.ps1`. They throw `ItemNotFoundException: Cannot find path '\\wsl.localhost\...\bin\..\wsl.localhost\...\lib\install\install-npm-global.ps1'`. On a drive-letter path (CI) they pass.

Reproduce from WSL:

```bash
W=$(wslpath -w ~/dev/xxthunder/shortcuts); pwsh.exe -NoProfile -ExecutionPolicy Bypass -File "${W}\test\bin\testrunner.ps1" -TestPath "bin\keypirinha-profile.Tests.ps1"
```

Root cause: the test takes the repository root from `Resolve-Path (Join-Path $PSScriptRoot '..')`. On a UNC path, `Resolve-Path` returns a provider-qualified path that still holds the `..` (`Microsoft.PowerShell.Core\FileSystem::\\wsl.localhost\...\bin\..`). `[System.IO.Path]::GetRelativePath` does not understand that form, so the relative file names and the paths joined from them are wrong.

**Scope Decisions**:
- **Fix the test, not the scripts**: only the repository root in the test is wrong; the scripts it checks are fine.
- **The red test is the UNC run**: the failure shows only on a UNC path, so the reproduction above is the failing test of the TDD cycle; no extra test is written for the test.

**Acceptance Criteria**:
- [x] `bin/keypirinha-profile.Tests.ps1` passes with the repository on a UNC path
- [ ] It still passes on a drive-letter path (CI)
- [ ] All existing tests continue to pass
