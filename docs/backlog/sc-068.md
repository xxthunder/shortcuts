# [SC-068] Distribution table: tell the WSL architecture from the WSL version

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/commands.ps1` (`Show-WslDistroTable`), `lib/wsl/commands.Tests.ps1`, `docs/wsl-manager.md`
**Related**: [SC-016c](sc-016c.md) (distro table), [SC-064](sc-064.md) (`Get-WslPlatformVersion`), [SC-063](sc-063.md) (WSL 3.0)

**Summary**:
As a user with WSL 3.0 installed, I want the distribution table to show the WSL version and the architecture of each distribution as two different things, so that "WSL2" in the table does not look like a stale or wrong version.

**Description**:
The `Version` column of `Show-WslDistroTable` shows `WSL$($distro.Version)`, e.g. `WSL2`. The number comes from the VERSION column of `wsl.exe --list --verbose`, which is the architecture of the distribution: 1 or 2. The version of WSL itself (`wsl --version`, e.g. 3.0.1.0 since SC-063) is a different number, and the table does not show it; only `update-wsl` reads it, through `Get-WslPlatformVersion`.

With WSL 3.0 installed, every distribution shows `WSL2`. The value is correct, but the label reads like the version of WSL, so it looks wrong.

Raised on 2026-10-22.

**Scope Decisions**:
- **Architecture column**: the column header becomes `Arch` and the value is the plain number (`1` or `2`) from `wsl --list --verbose`; no `WSL` prefix.
- **WSL version as the table title**: `Show-WslDistroTable` shows the version from `Get-WslPlatformVersion` as the table title, e.g. `WSL 3.0.1.0`. The title belongs to the table, so the TUI panel and the CLI `list` both show it.
- **Version unknown**: when `Get-WslPlatformVersion` returns `$null`, the title reads `WSL (version unknown)`, as in `update-wsl`, and the table still renders.
- **Not in scope**: `Get-WslDistroList` and its `Version` property stay as they are; `Test-Wsl2Version` and the other callers use the property and do not change.

**Acceptance Criteria**:
- [ ] The distribution table has an `Arch` column with the plain architecture number instead of the `Version` column with `WSL<n>`
- [ ] The table title shows the WSL version from `Get-WslPlatformVersion`, or `WSL (version unknown)` when it cannot be read
- [ ] The TUI panel and the CLI `list` both show the title
- [ ] Unit tests cover the `Arch` value for architecture 1 and 2, the title with a version and the title without one, with `wsl.exe` faked
- [ ] `docs/wsl-manager.md` describes the column and the title where it describes the table
