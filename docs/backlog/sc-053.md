# [SC-053] Scoop update helper must surface the `Info` column from `scoop status`

**Status**: Open
**Priority**: Medium
**Component**: `lib/scoop/scoop.ps1`, `lib/scoop/scoop.Tests.ps1`, `docs/runbooks/scoop-update.md`
**Related**: [SC-047](sc-047.md) (the update helper itself), [SC-052](sc-052.md) (incomplete `scoop status` results)

**Summary**:
As a developer using the Scoop update helper, I want apps that `scoop status` flags with an `Info` note to be shown with that note and excluded from bulk update selection, so that a broken install is diagnosable from the menu instead of appearing as a nonsensical version arrow.

**Description**:
`Get-ScoopUpdatableApp` (`lib/scoop/scoop.ps1:37`) maps only `Name`, `Installed Version`, and `Latest Version` from the `scoop status` output. `scoop status` also emits `Info` and `Missing Dependencies`; both are silently discarded. When an app has an `Info` note, `Latest Version` is typically empty, so `Show-ScoopUpdatableApp` (`lib/scoop/scoop.ps1:79`) renders:

```text
  1. thunderbird (152.0 -> )
```

The arrow points at nothing and the actual diagnosis, `Info: Manifest removed`, never reaches the user. Selecting the entry runs `scoop update thunderbird`, which cannot succeed while the underlying condition persists.

Observed on 2026-08-18 with `thunderbird` 152.0. The `Info` note read `Manifest removed`, but the manifest was present in the `extras` bucket at 153.0.3. The real cause was local: Thunderbird's own bundled updater had replaced scoop's `apps\thunderbird\current` junction with a real directory, leaving `apps\thunderbird\152.0` holding only `crashhelper.exe` and `updater.exe`. Scoop's `Get-Manifest` (`lib\manifest.ps1:51`) resolves `install.json` under the *version* directory, found nothing there, could not determine the bucket, and fell back to reporting `Manifest removed`. Repairing the junction and running `scoop update thunderbird` resolved it.

The scoop-side diagnosis was only reachable by running `scoop status` by hand. The helper had all the information and threw it away. That is what this item fixes; detecting or repairing broken junctions is explicitly out of scope.

**Scope Decisions**:

- **Carry `Info`, not every column.** `Missing Dependencies` is already actionable through scoop's own update output and adds a second empty column to the common case. Only `Info` is added to the returned object.

- **Render the note instead of the arrow, not in addition to it.** When `LatestVersion` is empty and `Info` is set, the line shows the note; when both are present, the arrow is shown with the note appended. An app with a note but no known latest version has nothing to update *to*, so printing `->` at all is misleading.

- **`[A]ll` skips noted apps with no latest version.** These cannot be updated by `scoop update <app>`; including them in the bulk selection guarantees a failing update on every run. They stay individually selectable so the user can still try.

- **Return contract extended, not replaced.** `Get-ScoopUpdatableApp` keeps returning an array of objects and gains one property. `Read-ScoopMenuChoice` and `Invoke-ScoopUpdate` signatures are unchanged. This composes with [SC-052](sc-052.md), which changes how the raw status output is split but not how a row is mapped.

- **Legacy text parsing stays as it is.** The legacy branch (`lib/scoop/scoop.ps1:52-72`) splits on whitespace runs and cannot reliably distinguish an `Info` note from a version column. It sets `Info` to an empty string.

**Acceptance Criteria**:

- [ ] `Get-ScoopUpdatableApp` maps the `Info` column from structured `scoop status` output into an `Info` property on each returned object
- [ ] The legacy text branch sets `Info` to an empty string and remains otherwise unchanged
- [ ] `Show-ScoopUpdatableApp` renders `name (installed -> latest)` unchanged when `Info` is empty
- [ ] `Show-ScoopUpdatableApp` renders the note and no arrow when `Info` is set and `LatestVersion` is empty
- [ ] `Show-ScoopUpdatableApp` renders the arrow plus the note when both `Info` and `LatestVersion` are set
- [ ] `Read-ScoopMenuChoice` excludes apps with a non-empty `Info` and an empty `LatestVersion` from the `[A]ll` selection, and still allows selecting them by number
- [ ] `lib/scoop/scoop.ps1` remains Windows PowerShell 5.1-compatible
- [ ] `scoop.Tests.ps1` covers the equivalence classes: no `Info`; `Info` with empty `LatestVersion`; `Info` with a `LatestVersion`; legacy text output; `[A]ll` over a mixed list
- [ ] `docs/runbooks/scoop-update.md` documents what an `Info` note means and names the broken-junction case with its manual repair
- [ ] Unit tests and PSScriptAnalyzer are clean; no new failures

**UAT Procedure**:

1. [ ] Launch the helper on a machine with only normal updatable apps; confirm the listing is unchanged.
2. [ ] Stub `Invoke-CommandLine` to return a row with `Info` set and an empty `Latest Version`; confirm the note is shown and no `->` appears.
3. [ ] Confirm `[A]ll` on that list selects the ordinary apps and skips the noted one.
4. [ ] Confirm the noted app can still be selected by its number.
