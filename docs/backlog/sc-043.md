# [SC-043] Trust the corporate TLS-inspection CA for tools with bundled cert stores (uv)

**Status**: In Progress (2026-07-17)
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/proxy.ps1`, `lib/wsl/proxy.Tests.ps1`, `docs/runbooks/px-proxy.md`
**Related**: [SC-042](sc-042.md) (WSL proxy env), [SC-040](sc-040.md) (Windows-side px)

**Summary**:
As a developer behind a TLS-inspecting corporate proxy, I want tools that ship their own CA bundle (uv, and other Rust/Go binaries) to trust the corporate root CA, so that HTTPS downloads through px succeed instead of failing with `UnknownIssuer`.

**Description**:
The corporate proxy performs **TLS inspection**: it terminates TLS and presents certificates signed by the corporate root CA rather than the origin's cert. `curl`/`wget` use the system CA bundle (`/etc/ssl/certs/ca-certificates.crt`), which contains the corporate CA, so they succeed through px. `uv` ships its own bundled roots (webpki-roots) and ignores the system trust store, so it rejects the inspected cert:

```
$ uv python install 3.11
error: Failed to install cpython-3.11.15-linux-x86_64-gnu
  Caused by: invalid peer certificate: UnknownIssuer
```

`wget` of the exact same URL through px returns `200` and downloads the 29 MB tarball, confirming the proxy path is fine and the corporate CA is present in the system store. This is **orthogonal to SC-042** (proxy routing works); it is a TLS-trust gap specific to tools with bundled CA stores. Go binaries and other reqwest-based Rust tools share the blind spot; Node has its own (`NODE_EXTRA_CA_CERTS`).

**Confirmed fixes** (2026-07-17, on the corporate machine):

```
SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt uv python install 3.11   # works
UV_SYSTEM_CERTS=1 uv python install 3.12                                   # works
UV_NATIVE_TLS=1 uv python install 3.13                                     # works, but warns: deprecated, use UV_SYSTEM_CERTS
```

**Scope Decisions**:
- **Fix location**: export the cert env in the same `/etc/profile.d/wsl-manager-proxy.sh` block that `setup-proxy` already writes (SC-042), so trust is inherited by all shells like the proxy vars and is removed on teardown.
- **Guard**: export conditionally (only when the bundle file is readable), so a missing bundle can never break TLS by pointing tools at a nonexistent file.
- **Variable set (decided 2026-07-17)**: export all five, each pointing at `/etc/ssl/certs/ca-certificates.crt` (or `/etc/ssl/certs` for the dir), for broad dev-stack coverage:
  - `SSL_CERT_FILE` + `SSL_CERT_DIR` — uv (confirmed), Go, reqwest, Python stdlib `ssl`
  - `NODE_EXTRA_CA_CERTS` — Node.js (ignores `SSL_CERT_FILE`)
  - `REQUESTS_CA_BUNDLE` + `PIP_CERT` — Python `requests`/`pip` (vendored certifi, ignore the system store)
  `UV_SYSTEM_CERTS` is not used: `SSL_CERT_FILE` already covers uv, so it would be redundant.
