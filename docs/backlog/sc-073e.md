# [SC-073e] codelinks markers in the px-proxy code and tests

**Status**: Open
**Priority**: Medium
**Component**: `tools/proxy/px-proxy.ps1`, `tools/proxy/px-proxy.Tests.ps1`, `ubproject.toml`, `AGENTS.md`
**Depends on**: [SC-073a](sc-073a.md) (released), [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want the px-proxy functions and Pester tests to carry codelinks markers naming the requirements they implement or test, so that every px-proxy requirement shows where it is implemented and which tests test it.

**Description**:
A codelinks one-line marker sits in a comment above what it annotates:

- above a function: `# @<title>, <id>, impl, [<requirements>]`
- above a Pester `It`: `# @<title>, <id>, test, [<requirements>]`, plus the Pester path the result is matched on (SC-073d), unless codelinks fills it (SC-073a)

The fields and their order are configured in `ubproject.toml`; a link to the component (SC-073f) may be a further link field on implementation markers.

**Scope Decisions**:
- **Markers in px-proxy's own code**: a generic helper in `lib/` that px-proxy calls (such as `Register-Autostart`) is traced at px-proxy's call site, not in the library.
- **Agents write markers as part of TDD** for a tool that has a requirements file: the test marker with the test, the implementation marker with the code. `AGENTS.md` says so, or every agent pull request fails the gate.

**Acceptance Criteria**:
- [ ] Every function in `tools/proxy/px-proxy.ps1` and every `It` in `tools/proxy/px-proxy.Tests.ps1` carries a marker, or is listed here with the reason it has none
- [ ] Every px-proxy requirement shows at least one implementation and one test, in ubCode and in the Sphinx build
- [ ] A px-proxy function without a marker, or a requirement without an implementation or a test, fails the documentation build
- [ ] `AGENTS.md` asks for markers in tools that have a requirements file
