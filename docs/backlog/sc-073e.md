# [SC-073e] codelinks markers in the px-proxy code

**Status**: Open
**Priority**: Medium
**Component**: `tools/proxy/px-proxy.ps1`, `ubproject.toml`, `AGENTS.md`
**Depends on**: [SC-073a](sc-073a.md) (released), [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want the px-proxy functions to carry codelinks markers naming the requirements they implement, so that every px-proxy requirement shows where it is implemented.

**Description**:
A codelinks one-line marker sits in a comment above the function it annotates: `# @<title>, <id>, impl, [<requirements>]`. The fields and their order are configured in `ubproject.toml`; a link to the component (SC-073f) may be a second link field.

**Scope Decisions**:
- **Markers in px-proxy's own code**: a generic helper in `lib/` that px-proxy calls (such as `Register-Autostart`) is traced at px-proxy's call site, not in the library.
- **Agents write markers as part of TDD** for a tool that has a requirements file; `AGENTS.md` says so, or every agent pull request fails the gate.

**Acceptance Criteria**:
- [ ] Every function in `tools/proxy/px-proxy.ps1` carries a marker, or is listed here with the reason it has none
- [ ] Every px-proxy requirement shows at least one implementation, in ubCode and in the Sphinx build
- [ ] A px-proxy function without a marker, or a requirement without an implementation, fails the documentation build
- [ ] `AGENTS.md` asks for markers in tools that have a requirements file
