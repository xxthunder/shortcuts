# [SC-094] The gate as a script in the repository

**Status**: Open
**Priority**: Medium
**Component**: `scripts/gate.ps1` (new), `AGENTS.md`
**Related**: [SC-073b](sc-073b.md) (`ubc check` in CI)

**Summary**:
As the maintainer, I want one script in the repository that runs every check a change must pass locally, so that an agent and I run the same gate without assembling it from prose.

**Description**:
An agent that works on shortcuts in a closed loop needs a gate: one command that runs the deterministic checks and exits 0 only when all of them pass. shortcuts has no such command. Today the loop builds the gate at every start from a prose description kept outside the repository:

- `powershell.exe -NoProfile -File test\bin\smoke-ps51.ps1`
- `pwsh.exe -File test\bin\testrunner.ps1 -Unit`
- `uv run poe docs`
- the integration tests of the files a change adds or changes, but never those in `lib\wsl` (they run real `wsl` commands and stop the distribution the session runs in), and not yet those in `bin\install`, `lib\scoop` and `lib\utils` (not checked for changes to the Windows machine)
- coverage for the same paths, each changed `.ps1` at or above the base coverage that `codecov/patch` and `codecov/project` ask for

Each step is mechanical, but an agent rebuilds the list, picks the integration tests and reads the coverage by hand every time. That is slow, and it can go wrong without anyone noticing. `ubc check` (SC-073b) runs in CI but is in no local list yet.

A script in the repository is the single source: the loop finds it through a `Closed loop` section in `AGENTS.md`, and the description outside the repository can go.

CI stays as it is. It runs the full suite on a fresh runner, which the local gate cannot do safely.

*`ubc check` and the test report* (2026-11-25). `ubc check` reads the Pester results from `test/out/junit.xml`. A local run on `develop` failed with two `needs.schema_definition_violation` errors (`result_of` required) because the file was from 2026-11-10: it held results of px-proxy tests that SC-087 had renamed since, so no test marker matched them. With the report of the latest CI run on `develop`, the same check passed. Three cases, as `ubc` 0.40.0 and `ubproject.toml` handle them:

- A stale report fails the check: its results point to tests that no longer exist.
- A partial report passes: a test without a result has the verdict "not run" (`ubproject.toml`, `[needs.fields.verdict]`), which is no error.
- No report gives `warning[needs.test_report_missing]`; whether `ubc` then exits non-zero is not checked yet.

All Pester tests run on Windows, the local ones too, so the place the results come from is not the problem. The local gate runs a subset of the tests, so its report is always partial: the traces it checks are right, the verdicts are complete only in CI.

**Scope Decisions**:
- **The gate writes its own report before `ubc check`** (author, 2026-11-25): it removes `test/out/junit.xml`, runs its tests, which write a fresh partial report, and then runs `ubc check`. Tests outside the subset show "not run" locally; the full verdicts come from CI. To see them locally, download the `pester-report` artifact of a CI run into `test/out/`.

**Open Questions**:
- Coverage: compare against the coverage of the base branch, or against a fixed threshold? Codecov's defaults compare with the base; a local run has no Codecov.
- `ubc` missing on the machine: fail the gate, or skip `ubc check` with a warning?
- Where `uv run poe docs` runs: Windows `uv` on the worktree's `\\wsl.localhost` path, or `uv` in WSL as today.

**Acceptance Criteria**:
- [ ] `scripts/gate.ps1` runs the smoke test, the unit tests, the integration tests and coverage of the changed files, `uv run poe docs` and `ubc check`
- [ ] The gate exits 0 only when every check passes; a test shows a non-zero exit when one check fails
- [ ] The gate removes `test/out/junit.xml` before its tests run, so `ubc check` reads only the report of this run
- [ ] The gate never runs the integration tests in `lib\wsl`, `bin\install`, `lib\scoop` or `lib\utils`
- [ ] `AGENTS.md` has a `Closed loop` section that names the gate and where it runs
- [ ] CI is green
