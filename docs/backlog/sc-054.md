# [SC-054] Podman and user unit tests must not reach the real wsl.exe

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/podman.Tests.ps1`, `lib/wsl/user.Tests.ps1`
**Related**: [SC-037](sc-037.md) (WSL Manager unit test coverage)

**Summary**:
As a contributor running the unit suite on my own machine, I want `podman.Tests.ps1` and `user.Tests.ps1` to pass regardless of which WSL distributions I have installed, so that a green unit run means the code is right and not that my machine happens to look like CI.

**Description**:
17 unit tests fail on any machine that has no distribution named `Debian`: the "Should accept Debian distribution" and default-user cases in `podman.Tests.ps1` (3 tests) and the `New-WslUser` cases in `user.Tests.ps1` (14 tests). They throw `Unable to determine state for distribution 'Debian'.` from `Get-WslDistroState` (`lib/wsl/core.ps1:238`).

The cause is an unmocked dependency chain. Both `Install-WslPodman` and `New-WslUser` finish by restarting the distribution through `Stop-WslDistro` (`lib/wsl/core.ps1`), which calls `Test-WslDistroRunning` -> `Get-WslDistroState` -> `Get-WslDistroList -Detailed` -> `wsl.exe --list --verbose`. The tests mock `Assert-WslDistroExists`, `Invoke-CommandLine`, `Invoke-WslDistroCommand` and `Start-Sleep`, but not `Stop-WslDistro` or anything below it, so the real `wsl.exe` is queried for a `Debian` that only exists on CI (the integration suites install it). Observed on 2026-09-12 during SC-016d, where the failures reproduced identically on an untouched `develop`.

This is a unit-test isolation gap, not a product bug: CI is green because CI has the distro. It matters because the project's rule that "there are no pre-existing failures" only holds if unit tests are hermetic; a contributor without `Debian` cannot tell their own regressions from the noise.

**Scope Decisions**:

- **Mock at the boundary the SUT owns, not deeper.** `Install-WslPodman` and `New-WslUser` call `Stop-WslDistro`; the tests should mock `Stop-WslDistro` (asserting it is invoked for the right distro) rather than `Get-WslDistroList`. Mocking deeper couples the tests to `Stop-WslDistro`'s internals, which `core.Tests.ps1` already covers.
- **No production code change.** The fix is entirely in the two test files. If a mock cannot be placed without changing production code, that is a finding to bring back to refinement, not a licence to refactor.
- **Guard against regression with a suite-level check.** A Pester test that asserts `wsl.exe` is never invoked during the unit run would catch the next leak; whether that belongs in `test/bin/` is decided during implementation and noted here.

**Acceptance Criteria**:
- [ ] `podman.Tests.ps1` and `user.Tests.ps1` pass on a machine whose installed distributions do not include `Debian`
- [ ] The affected tests mock `Stop-WslDistro` and assert it is called with the expected `-Name`
- [ ] No `.ps1` file outside the two test files changes
- [ ] The unit suite reports 0 failures on this machine (`wsl --list --verbose` showing no `Debian`) and on CI
- [ ] All existing tests continue to pass
