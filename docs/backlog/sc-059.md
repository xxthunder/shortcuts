# [SC-059] ✅ DONE - WSL Manager docs claim `configure-wsl` writes `autoProxy = true`

**Status**: Done (2026-09-28)
**Priority**: High
**Component**: `docs/wsl-manager.md`
**Related**: [SC-042](sc-042.md) (flipped the default to `false`), [SC-021](sc-021.md) (introduced `autoProxy=true`), [SC-041](sc-041.md) (px runbook)

**Summary**:
As a user setting up a WSL distribution behind the corporate proxy, I want the WSL Manager documentation to state what `configure-wsl` actually writes to `.wslconfig`, so that I do not turn `autoProxy` back on by hand and break the px workflow.

**Description**:
SC-042 changed the `autoProxy` default to `false` and made `Merge-WslConfig` force-overwrite that one key, because WSL's `autoProxy` injects the corporate proxy into every WSL shell and bypasses px (`407`). Code, unit tests and `docs/runbooks/px-proxy.md` (line 80) follow that decision. `docs/wsl-manager.md` was not updated and still describes the SC-021 behaviour:

- **Step 1: Configure WSL Global Settings** (line 122) lists "auto proxy" among the settings applied.
- **Configure .wslconfig defaults** (line 858) lists `[wsl2] autoProxy = true` (applies Windows proxy settings).
- The same section (line 854) says the defaults are merged "without overwriting existing user values". Since SC-042 that is wrong for `autoProxy`: an existing `autoProxy = true` is overwritten with `false`.

The two documents contradict each other on the setting the whole corporate-proxy setup depends on. A reader who follows `wsl-manager.md`, or who "repairs" `.wslconfig` to match it, sets `autoProxy = true` and gets the corporate proxy in every WSL shell again: `curl`, apt, Podman and DevPod builds fail with `407` although px is running. The next `configure-wsl` would silently flip it back, which makes the failure look intermittent.

Found on 2026-09-27 while documenting the devcontainer setup of the ESE repositories on the company machine, which relies on px, `networkingMode=mirrored` and `autoProxy=false`.

**Scope Decisions**:
- **Documentation only.** The code is correct (`lib/wsl/ops.ps1`, `Invoke-ConfigureWsl` and `Merge-WslConfig`); no behaviour changes.
- **State the reason where the setting is listed.** One sentence next to `autoProxy = false` saying why (it would inject the corporate proxy and bypass px) and a link to `docs/runbooks/px-proxy.md`, so the value does not look like an accident.
- **Not in scope**: other drift in `wsl-manager.md`.

**Acceptance Criteria**:
- [x] Step 1 in `docs/wsl-manager.md` no longer lists "auto proxy" as enabled; it says `autoProxy` is turned off
- [x] **Configure .wslconfig defaults** lists `[wsl2] autoProxy = false` with the reason and a link to the px runbook
- [x] The same section states that `autoProxy` is force-overwritten while all other keys are only added when missing
- [x] `grep -rn -i "autoproxy" docs README.md` shows no statement that contradicts `lib/wsl/ops.ps1`
