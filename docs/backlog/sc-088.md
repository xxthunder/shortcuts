# [SC-088] A failed Ubuntu install in the Podman integration test shows its cause

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/manager.podman.Integration.Tests.ps1`, `lib/wsl/install.ps1`

**Summary**:
As the author, I want a failed Ubuntu install in the Podman integration test to say why it failed, so that a red CI run tells me at once whether my branch or the runner broke it.

**Description**:
On 2026-11-11 around 16:10 UTC three CI runs failed at the same spot: both runs of PR #105 (SC-086, runs 43055710112 and 43055709364) and the push to `develop` for SC-073g (run 43055696040). The next push to `develop`, at 16:46, passed, and PR #105 itself changes nothing under `lib/wsl/`.

When the runner has no `Ubuntu`, the test's first case creates it through `Invoke-WslManager -Command install`, which runs `wsl.exe --install --distribution Ubuntu --no-launch` (`New-WslDistro`, `lib/wsl/install.ps1:136`). That call failed after about 7 s with exit code -1. The log then shows only:

- `WriteErrorException: Command line call "wsl.exe --install --distribution Ubuntu --no-launch" failed with exit code -1`
- twelve follow-on failures, `Distribution 'ubuntu-podman-test' does not exist`, one for each later case

What `wsl.exe` printed is lost: the test captures the install's output with `*>&1 | Out-String` and prints it only after the call returns, so a throw skips the print. Thirteen red tests stand for one cause, and the cause is not in the log.

**Acceptance Criteria**:
- [ ] When the install of the base distribution fails, the CI log shows `wsl.exe`'s own output for it
- [ ] The failure is reported once, by the case that creates the base distribution; the later cases do not add one follow-on error each
- [ ] All existing tests continue to pass

**Open Questions**:
- Retry: should a failed `wsl.exe --install` be tried again before the test fails, and if so in the test or in `New-WslDistro`? Decide once the visible output shows what the failures are.
