# [SC-052] Scoop update helper must not silently drop apps when `scoop status` fails

**Status**: Open
**Priority**: Medium
**Component**: `lib/scoop/scoop.ps1`, `lib/scoop/scoop.Tests.ps1`, `test/bin/smoke-ps51.ps1`, `docs/runbooks/scoop-update.md`
**Related**: [SC-047](sc-047.md) (the update helper itself), SPLE-2590 (upstream fix in the SPLE Scoop fork)

**Summary**:
As a developer using the Scoop update helper, I want to be told when `scoop status` could not evaluate some of my apps, and to be offered a repair for the known cause, so that outdated tools cannot stay invisible because the helper silently reported a shorter list than reality.

**Description**:
`Get-ScoopUpdatableApp` (`lib/scoop/scoop.ps1:37`) is the *only* source of the app list for `Invoke-ScoopUpdate` (`lib/scoop/scoop.ps1:301` and `:315`). It runs `scoop status` and parses the result. When `scoop status` fails for individual apps, those apps are dropped from the report, the helper shows a shorter list (or "All apps are up to date!"), and nothing indicates that the list is incomplete.

This is not hypothetical. On a corporate workstation, 15 apps installed from the SPLE bucket were affected:

```text
Where-Object : The 'Ine' operator failed: The term 'Get-UserAgent' is not recognized ...
At ...\libexec\scoop-status.ps1:58 char:26
```

Root cause (proven by dot-sourcing the same libraries as `scoop-status.ps1` and calling `app_status` with and without `lib/download.ps1`): `app_status` (`lib/core.ps1:557`) calls `manifest $app $install_info.bucket $install_info.url`. When `install.json` carries a `url`, `manifest()` routes to `url_manifest` (`lib/manifest.ps1:18`), which calls `Get-UserAgent`. Upstream PR 6095 moved that function from `lib/core.ps1` into `lib/download.ps1`, and `scoop-status.ps1` is the one command that does not dot-source `download.ps1`. Upstream fixed this (master and v0.5.3 carry the import at line 9); the SPLE fork is pinned at a commit inside the regression window, tracked as **SPLE-2590**.

The scoop-side defect is therefore someone else's to fix, and the affected workstation was repaired by hand. What remains ours is the failure mode this exposed: **our helper treats a partially failed `scoop status` as an authoritative complete list.** Any future scoop-side breakage will silently under-report again.

**Scope Decisions**:

- **Two independent guards, not one.** A generic guard (any `scoop status` failure becomes visible) plus a specific guard (detect and repair the known `url`-pinned cause). The generic guard alone would leave the user with a warning and no remedy; the specific guard alone would not survive the next unrelated scoop bug.

- **Error capture via `2>&1`, not `$Error` inspection.** `scoop` resolves to `C:\Users\<user>\scoop\shims\scoop.ps1` (an `ExternalScript`, verified with `Get-Command`), so it runs **in-process** and its non-terminating errors are `ErrorRecord` objects. `Get-ScoopUpdatableApp` therefore calls `scoop status 2>&1` and splits the result on `$_ -is [System.Management.Automation.ErrorRecord]`. Inspecting `$Error` around the call would be indirect and order-sensitive by comparison.

- **The split must precede the modern/legacy branch detection.** The existing parser probes the *first* item for a `Name` property to choose between structured-object and text parsing (`lib/scoop/scoop.ps1:45-46`). Merged error records arrive **before** the data, so an unfiltered first item would fail the probe and route perfectly good `PSCustomObject` output into the legacy text parser, producing garbage. Filter first, then detect.

- **Return contract unchanged.** `Get-ScoopUpdatableApp` keeps returning an array of `@{Name; InstalledVersion; LatestVersion}` and reports incompleteness through `Write-WarningMsg`, not through a new wrapper object or an extra flag. This keeps `Invoke-ScoopUpdate`, `Show-ScoopUpdatableApp`, `Read-ScoopMenuChoice`, and the existing `smoke-ps51.ps1` assertions untouched.

- **Bucket lookup must be recursive.** Buckets are not laid out uniformly: `main` and `extras` keep manifests under a `bucket\` subdirectory, while the `sple` bucket keeps them at the repository root. `Get-ScoopUrlPinnedApp` resolves a manifest by recursive search under `$root\buckets\<bucket>`, the same way scoop's own `manifest_path` does, instead of assuming either layout.

- **Repair writes files the 5.1 way.** `lib/scoop/scoop.ps1` must stay Windows PowerShell 5.1-compatible (ADR 0001), and `Set-Content -Encoding utf8NoBOM` is PowerShell 6+. `Repair-ScoopInstallInfo` writes via `[System.IO.File]::WriteAllText($path, $json, [System.Text.UTF8Encoding]::new($false))`, matching how scoop's own `save_install_info` writes the file (no BOM).

- **Repair is offered once at startup, not per loop iteration.** `Invoke-ScoopUpdate` loops on `Get-ScoopUpdatableApp`; warning on every iteration would be noise. The health check runs once after the startup bucket refresh. When repairable apps exist and the session is interactive, a `y/N` prompt (default No) offers the repair; when `Test-RunningInCIorTestEnvironment` is `$true` the prompt is skipped and only the warning is emitted, so CI never blocks.

- **Repair is opt-in and reversible.** Every rewritten `install.json` is copied to `install.json.bak` first. Apps whose `url` has no matching bucket manifest are genuinely external and are reported but never modified.

- **No new executable or menu entry.** The repair is reached through the startup prompt only. Adding an `[F]ix` action to the menu (SC-047's `A`/`R`/`Q` table) would spend permanent UI surface on a rare one-off migration.

**Design**:

New functions in `lib/scoop/scoop.ps1`:

| Function | Purpose | Returns |
|----------|---------|---------|
| `Get-ScoopUrlPinnedApp` | Enumerate `$env:SCOOP\apps\*\current\install.json` (falling back to `$env:USERPROFILE\scoop`) and report apps carrying a `url` | Objects with `Name`, `Url`, `Manifest`, `Bucket`, `Repairable` |
| `Repair-ScoopInstallInfo` | Rewrite repairable entries to `"bucket": "<name>"`, preserving all other keys | Objects describing each app repaired or skipped |

Changed behavior in `Get-ScoopUpdatableApp`:

```text
raw    = scoop status 2>&1                  # in-process, so errors are ErrorRecords
errors = raw where $_ -is [ErrorRecord]
data   = raw where $_ -isnot [ErrorRecord]
if errors: Write-WarningMsg "scoop status reported N error(s); this list may be incomplete" + the messages
parse data                                  # existing modern/legacy branch, unchanged
```

Changed behavior in `Invoke-ScoopUpdate`, once after the startup bucket refresh:

```text
pinned = Get-ScoopUrlPinnedApp
if pinned: warn, naming the apps and whether each is repairable
if any repairable and not CI/test: prompt y/N -> Repair-ScoopInstallInfo
```

**Acceptance Criteria**:

- [ ] `Get-ScoopUpdatableApp` invokes `scoop status 2>&1` and separates `ErrorRecord` items from data items before any branch detection
- [ ] When `scoop status` emits error records, `Get-ScoopUpdatableApp` warns that the list may be incomplete and surfaces the error text; the parsed apps are still returned
- [ ] Structured (`PSCustomObject`) status output preceded by error records is still parsed by the modern branch, not the legacy text branch
- [ ] `Get-ScoopUpdatableApp` still returns objects with `Name`, `InstalledVersion`, `LatestVersion` and no caller signature changes
- [ ] `Get-ScoopUrlPinnedApp` reports every app whose `install.json` contains a non-empty `url`, marking `Repairable` when a same-named manifest is found by recursive search in a local bucket (both `bucket\`-subdirectory and repository-root bucket layouts)
- [ ] `Repair-ScoopInstallInfo` replaces `url` with `bucket` while preserving other keys (e.g. `architecture`), backs the file up to `install.json.bak`, and writes UTF-8 without BOM via `[System.IO.File]::WriteAllText`
- [ ] `Repair-ScoopInstallInfo` leaves non-repairable and malformed entries untouched and reports them
- [ ] `Invoke-ScoopUpdate` runs the check exactly once at startup (not per loop iteration) and warns when url-pinned apps exist
- [ ] In CI/test (`Test-RunningInCIorTestEnvironment` true) the repair prompt is skipped and no `Read-Host` is called
- [ ] `lib/scoop/scoop.ps1` remains Windows PowerShell 5.1-compatible; `test/bin/smoke-ps51.ps1` asserts the new functions are defined under 5.1
- [ ] `scoop.Tests.ps1` covers the equivalence classes: no `url`; `url` with manifest in bucket; `url` with no matching manifest; raw-http `url` whose basename matches a bucket manifest; malformed `install.json`; app directory without `install.json`
- [ ] `docs/runbooks/scoop-update.md` documents the warning, the repair, and the SPLE-2590 background
- [ ] Unit tests and PSScriptAnalyzer are clean; no new failures

**UAT Procedure**:

1. [ ] On a machine with an app whose `install.json` contains a `url`, launch the helper; confirm a startup warning names the app and offers the repair.
2. [ ] Accept the repair; confirm `install.json` now has `"bucket"`, `architecture` is preserved, `install.json.bak` exists, and the file has no BOM.
3. [ ] Re-launch; confirm no warning appears and `scoop status` lists the app normally.
4. [ ] Decline the repair on a second app; confirm the file is unmodified and the helper still works.
5. [ ] Point an app's `url` at a manifest that exists in no bucket; confirm it is reported as not repairable and never modified.
6. [ ] Simulate a failing `scoop status` (e.g. shadow-stub `Invoke-CommandLine` to emit an error record plus one app); confirm the incompleteness warning appears and the app is still listed.
