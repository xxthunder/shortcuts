# [SC-077] One status per test and requirement, passed only when all tests passed

**Status**: Open
**Priority**: Medium
**Component**: `ubproject.toml`, `docs/traceability/px-proxy.md`
**Related**: [SC-073d](sc-073d.md)

**Summary**:
As a reader of the traces, I want a requirement to show passed only when all its tests passed, and a test card to show its status once, so that the status means what it says.

**Description**:
SC-073d derives the status with a `min` over an ordered `result` (failed, error, passed, skipped, disabled, not run): a derived field with nothing to read has no value, and a `default` is refused beside `derive`, so each test holds `result = "not run"` of its own, and its `verdict` is the `min` over its results and itself. Two things follow that read wrong:

- **A requirement's passed is not "all tests passed".** Its `verdict` is the worst verdict of its tests, and not run sorts after passed. A requirement with one passed and one not-run test shows passed.
- **A test card shows two outcomes.** It carries the helper value `result: not run` next to its real status `verdict: passed`, as on `TEST_PX_DATA_DIR_UNDER_PROFILE`. The test's status is one value; `result` belongs to the result need.

Raised on 2026-10-27.

**Scope Decisions**:
- **Passed means all tests passed** (author, 2026-10-27): a requirement is passed when every test of it passed, not run as soon as one of them did not run, and failed when one failed.
- **One field, one name**: tests and requirements show their status in one field of the same name, one that reads as the status; the helper value does not show on any card. Whether that takes a hidden helper field or another construction is decided here, for both sphinx-needs and ubCode.

**Acceptance Criteria**:
- [ ] A requirement with one passed and one not-run test shows not run; with all tests passed it shows passed; with one failed it shows failed
- [ ] A test card shows one status field and no `result` of its own
- [ ] Tests and requirements use the same field name for their status
