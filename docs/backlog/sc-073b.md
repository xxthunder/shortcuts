# [SC-073b] Documentation build and trace gate

**Status**: In Progress
**Priority**: Medium
**Component**: `ubproject.toml` (new), `conf.py` (new), a Python project file for the documentation toolchain (new), `.github/workflows/`
**Related**: [SC-065](sc-065.md) (devcontainer)

**Summary**:
As the maintainer, I want one `ubproject.toml` that ubCode, `ubc` and a Sphinx build all read, built and checked in CI and published, so that a broken trace fails CI and the traces are visible without VS Code.

**Description**:
The setup follows useblocks/SPLed, which keeps `ubproject.toml` at the root as the only needs configuration and hands it to Sphinx through `needs_from_toml`. Lessons from there to carry over:

- Configuring a parser puts ubCode in parser mode: the document set is the parser's `include` list. Without one, ubCode also parses `AGENTS.md`, `README.md` and skill files as documents. The list must match what Sphinx builds.
- `ubc` ships inside the ubCode extension, not on PyPI or npm; CI installs it with `useblocks/ubc-action`. ubCode is free for open-source projects; whether the action still needs a licence key is checked on the "Run ubc in CI" page.
- Versions on 2026-10-23: sphinx-needs 9.1.0, sphinx-test-reports 3.0.1, ubCode 0.38.0.

**Scope Decisions**:
- **CI order**: the documentation job runs after the test job and takes `test/out/junit.xml` from it (SC-073d).
- **Published on GitHub Pages** from `develop`.
- **Docs-only no longer means `.md` only for this setup**: `ubproject.toml`, `conf.py` and the Python project file go through a pull request (AGENTS.md); a requirement or item edit is still a `.md` change and is checked by CI on push.
- **Decided in this item**: which documents the build includes (backlog, ADRs, architecture, requirements, runbooks, tool docs), and where the documentation toolchain runs locally (uv, the devcontainer of SC-065, or both).

**Acceptance Criteria**:
- [ ] `ubproject.toml` at the root is the only needs configuration; `conf.py` reads it; ubCode opens the repository without configuration findings
- [ ] The documentation builds with Sphinx `-W`, locally and in CI
- [ ] `ubc check` runs in CI and fails the job on a finding
- [ ] The documentation is published on GitHub Pages from `develop`
- [ ] A link to a need that does not exist fails CI (shown on a branch)
