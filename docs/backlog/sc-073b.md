# [SC-073b] Documentation build and trace gate

**Status**: In Progress
**Priority**: Medium
**Component**: `ubproject.toml` (new), `conf.py` (new), a Python project file for the documentation toolchain (new), `.github/workflows/`
**Related**: [SC-065](sc-065.md) (devcontainer)

**Summary**:
As the maintainer, I want one `ubproject.toml` that ubCode, `ubc` and a Sphinx build all read, built and checked in CI and published, so that a broken trace fails CI and the traces are visible without VS Code.

**Description**:
The setup follows useblocks/SPLed, which keeps `ubproject.toml` at the root as the only needs configuration and hands it to Sphinx through `needs_from_toml`. Lessons from there to carry over:

- Configuring a parser puts ubCode in parser mode: the document set is the parser's `include` list. Without one, ubCode also parses `AGENTS.md`, `README.md` and skill files as documents. The list must match what Sphinx builds.
- `ubc` ships inside the ubCode extension, not on PyPI or npm; CI installs it with `useblocks/ubc-action`. ubCode is free for open-source projects; whether the action still needs a licence key is checked on the "Run ubc in CI" page.
- Versions on 2026-10-23: sphinx-needs 9.1.0, sphinx-test-reports 3.0.1, ubCode 0.38.0.
- `ubc` is also published on its own, per version, at `https://download.useblocks.com/ubc/<version>/ubc-linux-x64-<version>` (the URL `useblocks/ubc-action` uses); there is no `latest` path and no checksum file (checked 2026-11-25, ARDS-016 in ansible-role-dev-stack).

*The first `ubc check` with ubCode 0.40.0* (2026-11-25, on the branch of [SC-073a](sc-073a.md), sphinx-needs 9.3.0). `ubc build needs` and the Sphinx build give the same 1617 needs, with the same `title`, `implements`, `tests`, `constrains`, `result_of` and `verdict` on every need. So the traces agree. `ubc check` reports three configuration findings:

1. `info[config.derive_sphinx_minimum]` on `ubproject.toml`: the derived fields need sphinx-needs 9.0.0, the `join` 9.1.0, and ubCode cannot see which sphinx-needs the build uses. The lock pins 9.3.0, so the notice can be silenced with `ignore = ["config.derive_sphinx_minimum"]` under `[lint]`.
2. `warning[toctree.missing_root_document]` on `ubproject.toml`: root document `index` not found.
3. `warning[toctree.not_included]` on `docs/index.md`: the document is in no toctree.

2 and 3 have one cause: Sphinx reads its sources from `docs/` (`conf.py`), while ubCode takes the directory of `ubproject.toml` as the source directory and looks for `index` there. Two ways to close it, not decided yet:

- `[source] dir = "docs"` names the source directory Sphinx uses. The md parser's `include` patterns are then matched under `docs/`, so they lose their `docs/` prefix, and `conf.py`, which strips that prefix today, changes with them. To check: whether the `[codelinks]` `src_dir` paths stay relative to `ubproject.toml`. The agent's preference: it states the source directory once, for both readers.
- `[project] root_doc = "docs/index"` is one line, but it states the source directory a second time, next to `conf.py`.

**Scope Decisions**:
- **CI order**: the documentation job runs after the test job and takes `test/out/junit.xml` from it (SC-073d).
- **Published on GitHub Pages** from `develop`.
- **Docs-only no longer means `.md` only for this setup**: `ubproject.toml`, `conf.py` and the Python project file go through a pull request (AGENTS.md); a requirement or item edit is still a `.md` change and is checked by CI on push.
- **Decided in this item**: which documents the build includes (backlog, ADRs, architecture, requirements, runbooks, tool docs), and where the documentation toolchain runs locally (uv, the devcontainer of SC-065, or both).
- **The toolchain is uv** (author, 2026-10-24): `pyproject.toml` and `uv.lock` pin it, and `uv run poe docs` is the one build command, run alike locally and in CI. `-W` lives in that task and nowhere else.
- **The document set is the whole `docs/` tree** (author, 2026-10-24, in [SC-074](sc-074.md)): it started with `docs/index.md`, `docs/requirements/` and `docs/traceability/`, to grow with the slices that make backlog, ADRs, architecture and runbooks needs; SC-074 took in the rest at once, together with the user guide from the README. `conf.py` reads `include_patterns` from the md parser's `include` in `ubproject.toml`, so both readers build the same set.
- **Thin slice first** (author, 2026-10-24): a first pull request carries the build, CI with Pages, and the first px-proxy requirements and markers (SC-073c, SC-073e), so the codelinks pull request (SC-073a) can link a published example. `ubc check` follows in this item.
- **The documentation builds on Windows** (author, 2026-10-24): shortcuts is a Windows tool, so the documentation job runs on `windows-latest` in the CI workflow, after the test job, as the CI order above asks. It does not read the JUnit report yet; SC-073d adds that.
- **The root document is named in `ubproject.toml`** (author, 2026-11-25): `[project] root_doc = "docs/index"`. Tried in a scratch copy with `ubc` 0.40.0: it clears both toctree findings, and `conf.py` stays as it is. `[source] dir = "docs"` lost: it raised 19 `std.file_outside_roots` warnings for the `.md` files outside `docs/`, which would need an exclude list and a change to `conf.py`.
- **The sphinx-needs notice is silenced** (the agent's call): `ignore = ["config.derive_sphinx_minimum"]` under `[lint]`, because `pyproject.toml` pins `sphinx-needs>=9.3.0` (SC-073a).
- **`ubc check` runs in a Linux job of its own** (author, 2026-11-25): `useblocks/ubc-action` supports only Linux, and the documentation job runs on Windows. The new job runs after the test job, takes the Pester report from the `pester-report` artifact as the documentation job does, and pins `ubc` to 0.40.0. So `ubc` checks results and verdicts as well, not only the model and the markers. No licence key: the open-source check passes from the GitHub remote.
- **The CI job is the test** (author, 2026-11-25): in the closed loop, the tester adds the `ubc check` job to `.github/workflows/test.yml` and shows that `ubc check` fails on today's findings; the implementer changes `ubproject.toml` until it passes. The CI file stays out of the implementer's reach.
- **The loop shows the broken link** (author, 2026-11-25): it pushes a throwaway branch with one link to a need that does not exist, records the red CI run in the pull request, and deletes the branch.

**Acceptance Criteria**:
- [ ] `ubproject.toml` at the root is the only needs configuration; `conf.py` reads it; ubCode opens the repository without configuration findings
- [x] The documentation builds with Sphinx `-W`, locally and in CI
- [ ] `ubc check` runs in CI and fails the job on a finding
- [x] The documentation is published on GitHub Pages from `develop`
- [ ] A link to a need that does not exist fails CI (shown on a branch)
