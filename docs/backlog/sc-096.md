# [SC-096] CI runner freezes during the WSL integration tests

**Status**: Open
**Priority**: Medium
**Component**: `.github/workflows/test.yml`, `lib/wsl/manager.devstack.Integration.Tests.ps1`
**Related**: [SC-066a](sc-066a.md), [SC-095](sc-095.md)

**Summary**:
As a developer, I want the CI test job to finish or fail within its time limit, so that a pull request is never blocked by a run that hangs without a log.

**Description**:
During SC-066a (pull request 112), two of four CI runs with the new integration test froze in "Execute tests": the job ran past `timeout-minutes: 60` without being cancelled, and GitHub kept no job log (BlobNotFound). Both point at the Windows runner itself stopping to respond, not at a test waiting for input; a test that hangs would be cancelled at the limit and leave a log. The other runs of the same tree passed in about 20 minutes.

A resource probe in `manager.devstack.Integration.Tests.ps1` showed a healthy passing run: at least 22.6 GB free on the host's C:, at least 8.9 of 16 GB host memory free, and a WSL VM working set of at most 4.3 GB. Resource exhaustion is ruled out for that run; the cause of the freezes is unknown. The new integration test applies the dev-stack role up to three times to an Ubuntu distribution, including an apt dist-upgrade, Podman with user services and linger; the earlier suite installed Docker and Podman with shell scripts and did not freeze.

The comment on `timeout-minutes` in `test.yml` still names the Docker and Podman installs.

**Acceptance Criteria**:
- [ ] The cause of the freezes is found, or a freezing run leaves enough evidence to find it
- [ ] Ten consecutive CI runs of the test job finish within the time limit
- [ ] The comment on `timeout-minutes` in `.github/workflows/test.yml` describes what the job runs now
