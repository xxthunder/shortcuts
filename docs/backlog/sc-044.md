# [SC-044] Give px headroom for Claude Code connection bursts (workers/threads)

**Status**: In Progress (2026-07-17)
**Priority**: Medium
**Component**: `tools/proxy/px-proxy.ps1` (`Write-PxConfig`), `tools/proxy/px-proxy.Tests.ps1`
**Related**: [SC-040](sc-040.md) (px tool and config)

**Summary**:
As a developer using Claude Code (and similar tools) through px, I want px configured with more workers and threads so that parallel connection bursts don't exhaust px's small default pool and get refused.

**Description**:
`Write-PxConfig` omits `workers` and `threads`, so px runs on its low defaults (`workers = 2`, `threads = 5`). Claude Code fires many connections in parallel (multiple API calls, telemetry, tool fan-out); a burst can overflow the small worker/thread pool or the listen backlog, so some connections are refused while others succeed: the intermittent "from time to time" failures where px appears to briefly run out of capacity. `idle` and `socktimeout` are already raised above px defaults; the remaining gap is pool size.

**Fix**: add to the `[settings]` block of `px.ini` (values per px documentation):

```ini
workers = 8
threads = 32
```

(`idle = 60` and `socktimeout = 300.0` are already present.)

**Acceptance Criteria**:
- [x] `Write-PxConfig` writes `workers = 8` and `threads = 32` in the `px.ini` `[settings]` section
- [x] Existing config keys (`server`, `listen`, `port`, `log`, `idle`, `socktimeout`) are unchanged
- [x] `px-proxy` unit tests assert the new keys
- [x] No new test failures introduced (changed-area unit tests green; the 17 local `setup-user` failures are environmental and unchanged)

**UAT Procedure**:
1. [ ] Run `px-proxy start`; confirm `px.ini` contains `workers = 8` and `threads = 32`.
2. [ ] Under a Claude Code session, the intermittent connection refusals no longer occur.
