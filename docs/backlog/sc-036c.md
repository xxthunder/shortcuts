# [SC-036c] ✅ DONE - Negotiate mode Phases 2–3 — Kerberos + px activation

**Status**: Done (2026-06-01)
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy-negotiate.sh`, `lib/wsl/proxy.ps1`
**Depends on**: [SC-036b](sc-036b.md)
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer, I want the setup to configure Kerberos, write the px config, run `kinit` interactively, and verify the full chain so that I can confirm the Negotiate proxy works before any of my tools are switched over to it.

**Description**:
Implements Phases 2 and 3 of the SC-036 workflow:
- **Phase 2** — write `/etc/krb5.conf` (user-supplied realm + KDC), write `~/.config/px/px.ini` (no credentials), run `kinit` interactively (user enters Kerberos password in the terminal).
- **Phase 3** — start px and run `px --test` to verify the Kerberos ticket + upstream proxy work end-to-end.

After this slice, `curl -x http://localhost:3128 https://www.google.com` succeeds using only a Kerberos ticket. `.profile`, apt, Docker, and Podman are still in the Phase-1 Basic state — the switch to localhost happens in SC-036d.

**Scope Decisions**:
- **Auto-detected realm/KDC/principal defaults, user-confirmable** (revised after UAT): the realm, KDC, and principal prompts are pre-filled from the Windows domain session — realm = `$env:USERDNSDOMAIN` (uppercased), KDC = `$env:LOGONSERVER` promoted to an FQDN under that domain, principal = `$env:USERNAME`. The detected value is shown in the prompt (`Enter your Kerberos realm [MARQUARDT.DE]`) and the user presses Enter to accept or types an override. Off-domain the prompt falls back to free manual entry. **Why the change**: the original "no auto-discovery — user provides realm and KDC manually" decision failed UAT — a normal corporate user has no idea what their Kerberos realm/KDC are, so a blind prompt is a hard blocker. Detected-and-shown keeps the "explicit and auditable" intent (the value is visible and overridable) without making the user hunt for it. Detection lives in `Get-WindowsKerberosDefault` in `proxy.ps1`.
- **`kinit` runs against the corporate principal, not the WSL Linux user** (found in UAT): `kinit` with no principal defaults to the Linux login name (e.g. `wsluser@REALM`), which is not in the AD directory — `kinit: Client 'wsluser@MARQUARDT.DE' not found`. The principal is passed in via `--principal` (defaulting to `$env:USERNAME`) and qualified with the realm unless the user supplied a UPN-style `user@domain`.
- **`auth = NEGOTIATE` mandatory** in `px.ini`: px defaults to NTLM, which fails against a Kerberos-only upstream. Verified in the parent spec.
- **Verify with `curl` through px, not `px --test`** (found in UAT): `px --test`'s HTTPS sub-tests use a client that ignores the system CA bundle (`/etc/ssl/certs`), so they fail with curl error 60 against a corporate **TLS-inspecting** proxy even when Negotiate auth and the installed corporate root CA are both fine. `curl -x http://127.0.0.1:3128 https://…` honors the system trust store and is the authoritative end-to-end check (and matches the AC's success criterion). The diagnostic distinguishes a 407 (Kerberos/SPNEGO auth failure) from a TLS cert error (corporate root CA missing from the distro — a separate prerequisite, fixed with `update-ca-certificates`).
- **`listen = 127.0.0.1`, `port = 3128`**: `listen` is an IP (binding a port number there causes `[Errno 99] Cannot assign requested address`).
- **`kinit` runs interactively inside the script**: the user types their Kerberos password once; the ticket is immediately available for `px --test`. Alternative (defer `kinit` to the user's next shell) would leave us unable to verify in this slice.
- **Interactive invocation via `Start-Process -NoNewWindow -Wait -PassThru`** (found in UAT — `Invoke-WslExeInteractive`): `kinit` reads its password from `/dev/tty`, which only exists if WSL allocates a pty, which only happens when `wsl.exe`'s std handles are real console handles. The call operator (`& wsl.exe`) fails both ways: piping stdout to `Out-Host` shows output but drops the pty (`kinit` reports "Password incorrect" for a correct password), while not piping makes PowerShell capture the child's stdout (because the exit code is consumed up the chain) — swallowing output (blinking cursor) and *still* denying the pty. `Start-Process -NoNewWindow` hands the child the parent console directly (real pty, live I/O) and `-PassThru` returns the exit code without the pipeline touching stdout. The Phase-1 bootstrap stays on the stdin-pipe path (`Invoke-WslExeWithStdin`) — it is non-interactive and must keep secrets off the cmdline.
- **Failure policy — leave Phase-1 Basic state intact**: if `kinit` or `px --test` fails, emit a diagnostic and exit non-zero **without** touching `.profile`/apt/Docker/Podman. The user keeps a working Basic-auth proxy and can rerun or abandon without a half-migrated system. Marker file stays `negotiate-bootstrap`.
- **Idempotent re-run**: overwrite `/etc/krb5.conf` and `px.ini` on each run. Skip `kinit` if `klist -s` reports a valid ticket. Stop any running px before restarting.
- **px is verify-only in this phase; stopped before returning** (found in UAT): a persistent px daemon keeps the WSL session alive, so the one-shot `wsl.exe` invocation (`Start-Process -Wait`) never returns and the caller hangs after the completion banner — `setsid`/`nohup`/`</dev/null` detachment does **not** fix this; WSL waits for the session's processes regardless. Resolution: SC-036c starts px only long enough to run the curl verification, captures the result, then `pkill -x px` before `exit 0`. Nothing points at `localhost:3128` until SC-036d anyway, and the persistent px lifecycle (shell auto-start guarded by `klist -s`) is SC-036d's responsibility — that runs in the user's own interactive shell, which has no such hang.
- **Don't add env vars or bashrc block yet**: all localhost-switch work lives in SC-036d. This slice changes nothing about how existing tools reach the proxy.

**Technical Notes**:
- Minimal `/etc/krb5.conf`:
  ```ini
  [libdefaults]
      default_realm = CORP.COMPANY.COM

  [realms]
      CORP.COMPANY.COM = {
          kdc = kdc.company.com
          admin_server = kdc.company.com
      }

  [domain_realm]
      .company.com = CORP.COMPANY.COM
      company.com = CORP.COMPANY.COM
  ```
- Minimal `~/.config/px/px.ini`:
  ```ini
  [proxy]
  server = proxy.company.com:8080
  port = 3128
  listen = 127.0.0.1
  auth = NEGOTIATE
  ```
