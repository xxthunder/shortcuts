# [SC-036c] Negotiate mode Phases 2–3 — Kerberos + px activation

> **Superseded (2026-07-10)** by reusing the Windows-side px from [SC-040](sc-040.md); see [SC-036](sc-036.md) and [SC-036f](sc-036f.md). The in-WSL Kerberos activation is not being built. Kept for history and as a NAT-mode fallback.

**Status**: Superseded (2026-07-10)
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy-negotiate.sh`, `lib/wsl/proxy.ps1`
**Depends on**: [SC-036b](sc-036b.md)
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer, I want the setup to configure Kerberos, write the px config, run `kinit` interactively, and verify the full chain so that I can confirm the Negotiate proxy works before any of my tools are switched over to it.

**Description**:
Implements Phases 2 and 3 of the SC-036 workflow:
- **Phase 2** — write `/etc/krb5.conf` (user-supplied realm + KDC), write `~/.config/px/px.ini` (no credentials), run `kinit` interactively (user enters Kerberos password in the terminal).
- **Phase 3** — start px and run `px --test` to verify the Kerberos ticket + upstream proxy work end-to-end.

After this slice, `curl -x http://localhost:3128 https://www.google.com` succeeds using only a Kerberos ticket. `.profile`, apt, Docker, and Podman are still in the Phase-1 Basic state — the switch to localhost happens in SC-036d.

**Scope Decisions**:
- **No auto-discovery for krb5**: user provides realm and KDC manually. Explicit and auditable.
- **`auth = NEGOTIATE` mandatory** in `px.ini`: px defaults to NTLM, which fails against a Kerberos-only upstream. Verified in the parent spec.
- **`listen = 127.0.0.1`, `port = 3128`**: `listen` is an IP (binding a port number there causes `[Errno 99] Cannot assign requested address`).
- **`kinit` runs interactively inside the script**: the user types their Kerberos password once; the ticket is immediately available for `px --test`. Alternative (defer `kinit` to the user's next shell) would leave us unable to verify in this slice.
- **Failure policy — leave Phase-1 Basic state intact**: if `kinit` or `px --test` fails, emit a diagnostic and exit non-zero **without** touching `.profile`/apt/Docker/Podman. The user keeps a working Basic-auth proxy and can rerun or abandon without a half-migrated system. Marker file stays `negotiate-bootstrap`.
- **Idempotent re-run**: overwrite `/etc/krb5.conf` and `px.ini` on each run. Skip `kinit` if `klist -s` reports a valid ticket. Stop any running px before restarting.
- **Don't add env vars or bashrc block yet**: all localhost-switch work lives in SC-036d. This slice changes nothing about how existing tools reach the proxy.

**Acceptance Criteria**:
- [ ] `Install-WslProxy` prompts for Kerberos realm (e.g. `CORP.COMPANY.COM`) and KDC hostname (passed into the script)
- [ ] `setup-proxy-negotiate.sh` writes `/etc/krb5.conf` with the provided realm + KDC (root-owned)
- [ ] `setup-proxy-negotiate.sh` creates `~/.config/px/` if absent
- [ ] `setup-proxy-negotiate.sh` writes `~/.config/px/px.ini` with `server = <company proxy>`, `port = 3128`, `listen = 127.0.0.1`, `auth = NEGOTIATE`, no credentials
- [ ] `setup-proxy-negotiate.sh` runs `kinit` interactively unless `klist -s` reports a valid ticket
- [ ] `setup-proxy-negotiate.sh` starts px as a backgrounded process bound to `127.0.0.1:3128`
- [ ] `setup-proxy-negotiate.sh` runs `px --test` and emits a clear diagnostic on failure
- [ ] On `kinit` or `px --test` failure: script exits non-zero, marker remains `negotiate-bootstrap`, and `.profile`/apt/Docker/Podman are **not** modified
- [ ] On success: `curl -x http://localhost:3128 https://www.google.com` returns HTTP 200 (documented as the manual UAT step)
- [ ] Re-run: overwrites `krb5.conf` and `px.ini`, skips `kinit` if valid ticket exists, restarts px cleanly
- [ ] Pester unit tests cover the realm/KDC prompt branch in `Install-WslProxy`
- [ ] All existing tests continue to pass

**Technical Notes**:
- Minimal `/etc/krb5.conf`:
  ```ini
  [libdefaults]
      default_realm = CORP.COMPANY.COM

  [realms]
      CORP.COMPANY.COM = {
          kdc = kdc.company.com
          admin_server = kdc.company.com
      }

  [domain_realm]
      .company.com = CORP.COMPANY.COM
      company.com = CORP.COMPANY.COM
  ```
- Minimal `~/.config/px/px.ini`:
  ```ini
  [proxy]
  server = proxy.company.com:8080
  port = 3128
  listen = 127.0.0.1
  auth = NEGOTIATE
  ```
