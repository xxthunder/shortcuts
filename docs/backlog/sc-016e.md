# [SC-016e] Add Read-SpectreConfirm for destructive operations

**Status**: Open
**Priority**: High
**Component**: `lib/wsl/commands.ps1`, `lib/wsl/commands.Tests.ps1`, `lib/wsl/manager.ps1`, `lib/wsl/manager.Tests.ps1`, `docs/wsl-manager.md`
**Parent**: [SC-016](sc-016.md)
**Depends on**: [SC-016d](sc-016d.md)
**Related**: [SC-055](sc-055.md) (shares the skip-pause flag introduced here)

**Summary**:
As a user, I want destructive operations (remove, terminate, shutdown) to ask for explicit confirmation so that I do not accidentally destroy data or stop running distributions.

**Description**:
Every command in `commands.ps1` calls its operation with `-Confirm:$false` (`Invoke-RemoveDistro`, `Invoke-TerminateDistro`, `Invoke-ShutdownWsl`), so the TUI has no "are you sure" step anywhere: since SC-016d, removing a distribution is one Enter on the arrow-key picker. `Invoke-ShutdownWsl` prints the running distributions as a warning and then shuts down anyway.

Add a `Confirm-DestructiveAction` function wrapping `Read-SpectreConfirm` and wire it into the three destructive command functions. CLI paths (where `-Name` is provided) skip the confirmation to preserve scriptability.

### Technical approach

- New `Confirm-DestructiveAction -Action <text>` in `commands.ps1`: returns `$true` without prompting in CI/test; otherwise calls `Read-SpectreConfirm -Message "<text> Continue?" -DefaultAnswer n` and returns `$true` only for an explicit yes.
- `Invoke-RemoveDistro`: when `-Name` was empty (interactive), confirm after `Select-WslDistro` and before `Remove-WslDistro`; on deny, print `Cancelled.`, raise the skip-pause flag and return.
- `Invoke-TerminateDistro`: same, after the running-state validation and before `Stop-WslDistro`. The `-Name` path returns before the picker and is untouched.
- `Invoke-ShutdownWsl`: replace the printed warning with a confirmation whose text names the running distributions (or says none are running); the CLI `shutdown` command has no `-Name`, so it confirms too outside CI.
- Generalise SC-016d's `$script:WslPickerWentBack` into `$script:WslSkipContinuePause`; the picker's back entry and a denied confirmation both raise it.
- Tests: stub and mock `Read-SpectreConfirm` in `commands.Tests.ps1` and `manager.Tests.ps1`; cover confirmed, denied, CI, and CLI-with-name for each command.

### Scope Decisions

- **Default answer is No.** `Read-SpectreConfirm` defaults to `y` on a bare Enter (PwshSpectreConsole 2.6.x); for a destructive prompt that is the wrong default, so every call passes `-DefaultAnswer n`. Enter, `n`, or anything that is not an explicit yes cancels. Ctrl+C under the `.bat` wrapper is intercepted by `cmd.exe` (see SC-016d), so `n`/Enter is the documented cancel, not Ctrl+C.
- **CLI with `-Name` is trusted; the TUI is the guarded path.** `wsl-manager remove Ubuntu` and `wsl-manager terminate Ubuntu` keep deleting or stopping without a prompt, as today; scripts depend on that. The prompt fires only when the name came from the picker.
- **`shutdown` confirms outside CI even from the CLI.** It has no `-Name` to signal "scripted", and it stops every running distribution. In CI/test (`Test-RunningInCIorTestEnvironment`) it proceeds without a prompt, preserving the non-interactive path; a `-Force` switch is deliberately not added until someone needs it.
- **Confirmation lives in `commands.ps1`, not in the `lib/wsl` operations.** `Remove-WslDistro`, `Stop-WslDistro` and `Stop-WslSubsystem` already support `-Confirm` via `ShouldProcess`; the TUI bypasses that with `-Confirm:$false` and adds its own Spectre prompt, because the PowerShell `ShouldProcess` prompt is a plain-console dialog that does not match the Spectre TUI and cannot carry the running-distro list. The operations themselves are not changed (epic constraint).
- **A denied confirmation returns to the menu without the "Press Enter to continue" pause**, exactly like backing out of the picker. This is why the flag is generalised and renamed here; SC-055 reuses it rather than renaming again.
- **Plain text, no Spectre markup, in the prompt.** Distribution names are user data and could contain `[`; the message is built without markup so nothing needs escaping.

**Acceptance Criteria**:
- [ ] `Confirm-DestructiveAction` exists in `commands.ps1`, calls `Read-SpectreConfirm` with `-DefaultAnswer n`, and returns `$true` only on an explicit yes
- [ ] `Confirm-DestructiveAction` returns `$true` without prompting in CI/test environments
- [ ] `Invoke-RemoveDistro` prompts for confirmation in interactive mode and removes only on yes
- [ ] `Invoke-TerminateDistro` prompts for confirmation in interactive mode and terminates only on yes
- [ ] `Invoke-ShutdownWsl` prompts for confirmation naming the running distributions (or stating none are running) and shuts down only on yes
- [ ] Denying confirmation prints `Cancelled.`, aborts the operation, and returns to the menu without the "Press Enter to continue" pause
- [ ] CLI mode (direct `-Name` parameter) skips confirmation for remove and terminate
- [ ] `$script:WslPickerWentBack` is renamed to `$script:WslSkipContinuePause` in `commands.ps1`, `manager.ps1` and their tests, with unchanged behaviour for **Back to main menu**
- [ ] Pester unit tests cover confirmed, denied, CI, and CLI-with-name paths for all three commands, with `Read-SpectreConfirm` mocked
- [ ] `docs/wsl-manager.md` documents the confirmation for remove, terminate and shutdown, and that `-Name` on the CLI skips it
- [ ] All existing tests continue to pass
- [ ] UAT procedure below executed; all steps pass

### UAT Procedure

1. Run `tools\wsl-manager\wsl-manager.bat`, select **Remove distribution**, pick a throwaway distribution. Expected: a `Remove distribution '<name>'... Continue? [y/n] (n)` prompt with **n** as the default.
2. Press Enter. Expected: `Cancelled.`, then the main menu immediately (no "Press Enter to continue"); the distribution still exists.
3. Repeat and answer `y`. Expected: the distribution is removed, then the usual "Press Enter to continue".
4. Select **Terminate distribution** with a running distribution, pick it, answer `n`. Expected: `Cancelled.`, straight back to the menu, distribution still running.
5. Select **Shutdown WSL** while at least one distribution is running. Expected: the prompt names the running distributions; answer `n` and nothing is stopped; answer `y` and WSL shuts down.
6. CLI: `pwsh -File tools\wsl-manager\wsl-manager.ps1 remove <throwaway-name>`. Expected: removed without any prompt.
7. CLI: `pwsh -File tools\wsl-manager\wsl-manager.ps1 shutdown`. Expected: the confirmation prompt appears (no `-Name` exists for shutdown).
8. CLI in CI mode: `$env:CI = 1; pwsh -File tools\wsl-manager\wsl-manager.ps1 shutdown`. Expected: shuts down without a prompt. Then `Remove-Item Env:CI`.
