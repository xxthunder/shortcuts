# [SC-089] The install sets up the Shortcuts extension for Command Palette with both shortcuts folders

**Status**: Open
**Priority**: Medium
**Component**: `bin/install.ps1`, `docs/index.md`, `docs/architecture/workspace.dsl`, `docs/architecture/workspace.json`
**Related**: [SC-086](sc-086.md) (Command Palette on `Alt+Space`, which leaves the extension out), CmdPal.Extension.Shortcuts [CPS-010](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-010.md) (the extension in the Microsoft Store and the Extension Gallery) and [CPS-011](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-011.md) (its default becomes `shortcuts` only)

**Summary**:
As a user of the shortcuts install, I want it to install the Shortcuts extension for Command Palette and catalogue both `shortcuts` and `shortcuts_private`, so that my scripts and links appear on `Alt+Space` without configuring the extension by hand.

**Description**:
SC-086 sets Command Palette on `Alt+Space` but leaves the extension that catalogues the
shortcuts folders out: the extension was not yet released. CPS-010 publishes it through the
Microsoft Store and the Extension Gallery. With CPS-011 its default folder becomes
`%USERPROFILE%\shortcuts\**` only, since a stranger has no `shortcuts_private`; the install,
which creates `shortcuts_private`, is what adds it.

The install cannot rely on the Store. On managed work machines, group policy often removes the
Store, turns off the winget command line and blocks Developer Mode, while it still allows
packages that are signed by a trusted certificate. The author's work machine shows exactly this
(read on 2026-11-19): `RemoveWindowsStore` = 1, `EnableWindowsPackageManagerCommandLineInterfaces`
= 0, `AllowDevelopmentWithoutDevLicense` = 0 and `AllowAllTrustedApps` = 1; signed packages
from outside the Store are installed on it. Scoop, which the install already uses, can install
such a signed package for the current user.

Two steps for the install:
- **Install the extension** through scoop: a manifest downloads a signed `.msixbundle`;
  `post_install` runs `Add-AppxPackage` on it and `pre_uninstall` runs `Remove-AppxPackage`.
- **Set its folders** to `%USERPROFILE%\shortcuts\**` and `%USERPROFILE%\shortcuts_private\**`
  in the extension's settings file, the key `CmdPal.Extension.Shortcuts.Patterns`, keeping every
  other setting, as SC-086 does for Command Palette's hotkey.

Raised on 2026-11-14.

**Scope Decisions**:
- **Scoop with a signed bundle, not the Store** (the author, 2026-11-19): the install takes the
  extension from a scoop manifest that installs a signed `.msixbundle`. It needs no admin rights,
  no Developer Mode, no Store and no winget. The Store and the Extension Gallery stay the way for
  everyone outside the install (CPS-010).
- **Not winget with the `msstore` source** (2026-11-19): it needs both the Store and the winget
  command line, and managed machines can block both.
- **Not the unpacked layout** (2026-11-19): `uat.ps1` of CmdPal.Extension.Shortcuts registers the
  unpacked build with `Add-AppxPackage -Register`; Windows allows that only with Developer Mode,
  which policy can block and which users cannot be asked to turn on.
- **Not a self-signed certificate** (2026-11-19): Windows trusts it only after an administrator
  imports it into the machine's *Trusted People* store, on every machine.

**Acceptance Criteria**:
- [ ] `bin/install.ps1` installs the Shortcuts extension through scoop from a signed `.msixbundle`, without admin rights, Developer Mode, the Store or winget
- [ ] The install sets the extension's folders to `shortcuts` and `shortcuts_private` and keeps every other setting of the extension
- [ ] `docs/index.md` says the scripts and links of both folders appear in Command Palette's main search
- [ ] `docs/architecture/workspace.dsl` has the extension, and `workspace.json` matches it
- [ ] Unit tests, PSScriptAnalyzer and the required CI checks pass, `codecov/patch` included

**Dependencies**:
- CmdPal.Extension.Shortcuts: a release publishes a signed `.msixbundle` and a scoop manifest for it. No item for this exists yet; its signing certificate is the open question below.
- [SC-086](sc-086.md): Command Palette must be installed.

**Open Questions**:
- Which certificate signs the bundle? It must chain to a root that the target machines trust. Candidates: a public code-signing certificate, or one from the PKI that the managed machines already trust. Azure Artifact Signing is open to individual developers only in the USA and Canada.
- The bundle's `Publisher` must match the certificate's subject, so its package identity differs from the Store's. Can both be on one machine, and does the install need to remove a Store copy?
- Where is the settings file? The extension uses `Utilities.BaseSettingsPath("CmdPal.Extension.Shortcuts")`, which for a packaged app lies under `%LOCALAPPDATA%\Packages\<package family name>\LocalState\`; the family name follows from the signing identity.
- Does the file exist before the extension first runs? If not, the install writes it whole.
- Does `scoop update` register the new version over the old one while the extension runs, or must the manifest stop `CmdPal.Extension.Shortcuts` first?
