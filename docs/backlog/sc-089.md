# [SC-089] The install sets up the Shortcuts extension for Command Palette with both shortcuts folders

**Status**: Open
**Priority**: Medium
**Component**: `bin/install.ps1`, `docs/index.md`, `docs/architecture/workspace.dsl`, `docs/architecture/workspace.json`
**Related**: [SC-086](sc-086.md) (Command Palette on `Alt+Space`, which leaves the extension out), CmdPal.Extension.Shortcuts [CPS-010](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-010.md) (the extension in the Microsoft Store and the Extension Gallery), [CPS-011](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-011.md) (its default becomes `shortcuts` only) and [CPS-019](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-019.md) (the Store-signed bundle on GitHub and in WinGet)

**Summary**:
As a user of the shortcuts install, I want it to install the Shortcuts extension for Command Palette and catalogue both `shortcuts` and `shortcuts_private`, so that my scripts and links appear on `Alt+Space` without configuring the extension by hand.

**Description**:
SC-086 sets Command Palette on `Alt+Space` but leaves the extension that catalogues the
shortcuts folders out: the extension was not yet released. CPS-010 publishes it through the
Microsoft Store and the Extension Gallery. With CPS-011 its default folder becomes
`%USERPROFILE%\shortcuts\**` only, since a stranger has no `shortcuts_private`; the install,
which creates `shortcuts_private`, is what adds it.

The install cannot rely on the Store. On managed work machines, group policy often removes the
Store, turns off the winget command line and blocks Developer Mode, while it still allows
packages that are signed by a trusted certificate. The author's work machine shows exactly this
(read on 2026-11-19): `RemoveWindowsStore` = 1, `EnableWindowsPackageManagerCommandLineInterfaces`
= 0, `AllowDevelopmentWithoutDevLicense` = 0 and `AllowAllTrustedApps` = 1.

A Store-signed package installs there all the same. The Store re-signs an MSIX with a Microsoft
certificate that every Windows trusts, and the signature stays valid outside the Store. On the
same machine, Command Palette's Extension Gallery installed the extension ProcessKiller through
its WinGet button: the WinGet manifest points to a Store-signed `.Msixbundle` on the project's
GitHub release, and `Get-AppxPackage` reports it with `SignatureKind` `Store`. The policy blocks
`winget.exe` and the WinGet PowerShell module, not the WinGet COM API that Command Palette calls.
CPS-019 puts the extension's Store-signed bundle on its GitHub releases in the same way.

Two steps for the install:
- **Install the extension** through scoop: a manifest downloads the Store-signed `.msixbundle`
  from the extension's GitHub release; `post_install` runs `Add-AppxPackage` on it and
  `pre_uninstall` runs `Remove-AppxPackage`.
- **Set its folders** to `%USERPROFILE%\shortcuts\**` and `%USERPROFILE%\shortcuts_private\**`
  in the extension's settings file, the key `CmdPal.Extension.Shortcuts.Patterns`, keeping every
  other setting, as SC-086 does for Command Palette's hotkey.

A sketch of the install (2026-11-19), with placeholders for the version and the asset name:

1. CmdPal.Extension.Shortcuts is its own scoop bucket: scoop finds manifests in its `bucket/`
   folder. The manifest installs the release asset and removes the package on uninstall:

   ```json
   {
     "version": "1.2.0",
     "description": "Shortcuts extension for Command Palette (Store-signed)",
     "homepage": "https://github.com/xxthunder/CmdPal.Extension.Shortcuts",
     "url": "https://github.com/xxthunder/CmdPal.Extension.Shortcuts/releases/download/v1.2.0/CmdPal.Extension.Shortcuts.msixbundle",
     "hash": "<sha256>",
     "post_install": "Add-AppxPackage -Path \"$dir\\$fname\" -ForceApplicationShutdown",
     "pre_uninstall": "Get-AppxPackage karnomag.ShortcutsforCommandPalette | Remove-AppxPackage",
     "checkver": "github",
     "autoupdate": {
       "url": "https://github.com/xxthunder/CmdPal.Extension.Shortcuts/releases/download/v$version/CmdPal.Extension.Shortcuts.msixbundle"
     }
   }
   ```

2. `scoop_mandatory.json` adds the bucket and the app next to `keypirinha`, so
   `Install-MandatoryToolset` installs the extension and `scoop update` updates it:

   ```json
   { "Name": "cmdpal-shortcuts", "Source": "https://github.com/xxthunder/CmdPal.Extension.Shortcuts" }
   ```

   under `buckets`, and `{ "Source": "cmdpal-shortcuts", "Name": "cmdpal-shortcuts" }` under `apps`.

3. `bin/install.ps1` gets a post-install step after `New-Directory shortcuts_private`, next to
   the Keypirinha `Copy-Config`. It reads the extension's settings file, sets the key, and
   writes the file back with every other setting kept:

   ```powershell
   Set-ShortcutsExtensionPattern -Patterns @(
       "$Env:USERPROFILE\shortcuts\**",
       "$Env:USERPROFILE\shortcuts_private\**")
   ```

`checkver: github` reads the latest GitHub release, so it works only when every release
carries the Store-signed bundle (CPS-019).

Raised on 2026-11-14.

**Scope Decisions**:
- **Scoop with the Store-signed bundle** (the author, 2026-11-19): the install takes the extension
  from a scoop manifest that installs the Store-signed `.msixbundle` of the extension's GitHub
  release. It needs no admin rights, no Developer Mode, no Store, no winget command line and no
  certificate of its own. The package identity is the Store's, so a machine that has the Store
  gets the same package and its updates. The Store and the Extension Gallery stay the way for
  everyone outside the install (CPS-010, CPS-019).
- **Not `winget install`** (2026-11-19): the install runs `winget.exe`, which managed machines
  can turn off by policy; the COM API that Command Palette uses is no script interface.
- **Not the unpacked layout** (2026-11-19): `uat.ps1` of CmdPal.Extension.Shortcuts registers the
  unpacked build with `Add-AppxPackage -Register`; Windows allows that only with Developer Mode,
  which policy can block and which users cannot be asked to turn on.
- **No certificate of its own** (2026-11-19): a self-signed certificate needs an administrator
  to import it on every machine; a public or an organisation's certificate costs money or an
  approval and gives a second package identity. The Store's signature makes both unnecessary.

**Acceptance Criteria**:
- [ ] `bin/install.ps1` installs the Shortcuts extension through scoop from the Store-signed `.msixbundle`, without admin rights, Developer Mode, the Store or the winget command line
- [ ] The install sets the extension's folders to `shortcuts` and `shortcuts_private` and keeps every other setting of the extension
- [ ] `docs/index.md` says the scripts and links of both folders appear in Command Palette's main search
- [ ] `docs/architecture/workspace.dsl` has the extension, and `workspace.json` matches it
- [ ] Unit tests, PSScriptAnalyzer and the required CI checks pass, `codecov/patch` included

**Dependencies**:

**Open Questions**:
- Where does the scoop manifest live: a `bucket/` folder in CmdPal.Extension.Shortcuts, or in this repository? Decided with CPS-019.
- Where is the settings file? The extension uses `Utilities.BaseSettingsPath("CmdPal.Extension.Shortcuts")`, which for a packaged app lies under `%LOCALAPPDATA%\Packages\<package family name>\LocalState\`; the family name is the Store identity's, `karnomag.ShortcutsforCommandPalette_nsydvkza7yaey`.
- Does the file exist before the extension first runs? If not, the install writes it whole.
- Does `scoop update` run `pre_uninstall` before it installs the new version? Then the update removes the package and adds it again, and the settings under `LocalState` may be lost; `pre_uninstall` would then have to skip the removal during an update. `-ForceApplicationShutdown` in the sketch stops a running extension for the in-place upgrade.
- Does `Add-AppxPackage` run in the shell that calls scoop? Some PowerShell 7 versions load the Appx module only with `Import-Module Appx -UseWindowsPowerShell`; test the manifest in Windows PowerShell 5.1 and in PowerShell 7.
