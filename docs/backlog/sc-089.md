# [SC-089] The install sets up the Shortcuts extension for Command Palette with both shortcuts folders

**Status**: Open
**Priority**: Medium
**Component**: `bin/install.ps1`, `docs/index.md`, `docs/architecture/workspace.dsl`, `docs/architecture/workspace.json`
**Related**: [SC-086](sc-086.md) (Command Palette on `Alt+Space`, which leaves the extension out), CmdPal.Extension.Shortcuts [CPS-010](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-010.md) (the extension in the Microsoft Store) and [CPS-011](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-011.md) (its default becomes `shortcuts` only)

**Summary**:
As a user of the shortcuts install, I want it to install the Shortcuts extension for Command Palette and catalogue both `shortcuts` and `shortcuts_private`, so that my scripts and links appear on `Alt+Space` without configuring the extension by hand.

**Description**:
SC-086 sets Command Palette on `Alt+Space` but leaves the extension that catalogues the
shortcuts folders out: the extension was not yet released. It is being published through the
Microsoft Store (CPS-010). With CPS-011 its default folder becomes `%USERPROFILE%\shortcuts\**`
only, since a stranger has no `shortcuts_private`; the install, which creates
`shortcuts_private`, is what adds it.

Two steps for the install:
- **Install the extension** from the Microsoft Store, e.g. `winget install --source msstore <product ID>`.
- **Set its folders** to `%USERPROFILE%\shortcuts\**` and `%USERPROFILE%\shortcuts_private\**`
  in the extension's settings file, the key `CmdPal.Extension.Shortcuts.Patterns`, keeping every
  other setting, as SC-086 does for Command Palette's hotkey.

Raised on 2026-11-14.

**Acceptance Criteria**:
- [ ] `bin/install.ps1` installs the Shortcuts extension from the Microsoft Store
- [ ] The install sets the extension's folders to `shortcuts` and `shortcuts_private` and keeps every other setting of the extension
- [ ] `docs/index.md` says the scripts and links of both folders appear in Command Palette's main search
- [ ] `docs/architecture/workspace.dsl` has the extension, and `workspace.json` matches it
- [ ] Unit tests, PSScriptAnalyzer and the required CI checks pass, `codecov/patch` included

**Dependencies**:
- CmdPal.Extension.Shortcuts [CPS-010](https://github.com/xxthunder/CmdPal.Extension.Shortcuts/blob/develop/docs/backlog/cps-010.md): the extension must be in the Store, with its product ID.
- [SC-086](sc-086.md): Command Palette must be installed.

**Open Questions**:
- Where is the settings file? The extension uses `Utilities.BaseSettingsPath("CmdPal.Extension.Shortcuts")`, which for a packaged app lies under `%LOCALAPPDATA%\Packages\<package family name>\LocalState\`; the family name follows from the identity Partner Center reserves in CPS-010.
- Does the file exist before the extension first runs? If not, the install writes it whole.
