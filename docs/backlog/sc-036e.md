# [SC-036e] Mode-aware `--remove` teardown and Negotiate docs

> **Superseded (2026-07-10)** by reusing the Windows-side px from [SC-040](sc-040.md); see [SC-036](sc-036.md) and [SC-036f](sc-036f.md). There is no in-WSL px stack to tear down, so the mode-aware Negotiate teardown is not being built. Kept for history and as a NAT-mode fallback.

**Status**: Superseded (2026-07-10)
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/scripts/setup-proxy-negotiate.sh`, `lib/wsl/proxy.ps1`, `docs/wsl-manager.md`
**Depends on**: [SC-036d](sc-036d.md)
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer, I want `setup-proxy --remove` (or the equivalent DIRECT path in `wsl-manager`) to correctly tear down whichever mode was set up — Basic or Negotiate — so that re-running setup or moving to a different environment leaves the distro in a clean state.

**Description**:
Final slice of SC-036. Reads `/etc/wsl-manager/proxy-mode` to dispatch the right teardown:

- **`basic`**: existing SC-007 behavior — remove `.profile` managed block, `/etc/apt/apt.conf.d/99proxy`, Docker and Podman proxy configs. Delete the marker file last.
- **`negotiate` or `negotiate-bootstrap`**: stop any running px (`pkill -x px`), uninstall px via `pipx uninstall px-proxy`, delete `~/.config/px/`, strip the `.bashrc` managed block, then run the same Basic teardown for `.profile`/apt/Docker/Podman/marker.

Also documents Negotiate mode and the `kinit` prerequisite in `docs/wsl-manager.md`.

**Scope Decisions**:
- **Leave `/etc/krb5.conf` alone**: it is system-wide and the user may rely on Kerberos for other services (SSH, mounts, other tools). Removing it could silently break unrelated things. Teardown only removes what the setup script uniquely introduced.
- **Do not remove `krb5-user` or `pipx` packages**: the user may want them for other work. We remove `px-proxy` (ours) but leave the system packages we installed.
- **Kerberos ticket cache untouched**: `kdestroy` is not called. The ticket is harmless once px is gone; the user can destroy it themselves if they care.
- **Dispatch location**: `setup-proxy.sh --remove` reads the marker and, if it sees `negotiate*`, execs `setup-proxy-negotiate.sh --remove`. Single entry point from the PS1 side; the negotiate script owns its own teardown knowledge.
- **Missing marker**: if the marker file is missing, fall back to Basic teardown (conservative — this is what SC-007 did before SC-036 existed, so pre-SC-036 installs continue to teardown correctly).
- **Marker deletion last**: if teardown fails partway, the marker survives so a rerun still dispatches to the right mode.

**Acceptance Criteria**:
- [ ] `setup-proxy.sh --remove` reads `/etc/wsl-manager/proxy-mode` and, when the value starts with `negotiate`, execs `setup-proxy-negotiate.sh --remove`
- [ ] When the marker is absent, `setup-proxy.sh --remove` proceeds with the existing Basic teardown (backwards-compatible with pre-SC-036 installs)
- [ ] `setup-proxy-negotiate.sh --remove` stops any running px (`pkill -x px`, exit 0 even if none running)
- [ ] `setup-proxy-negotiate.sh --remove` uninstalls `px-proxy` via `pipx uninstall px-proxy`
- [ ] `setup-proxy-negotiate.sh --remove` deletes `~/.config/px/`
- [ ] `setup-proxy-negotiate.sh --remove` removes the managed block from `.bashrc` (and from legacy `.profile` location if present, for symmetry with SC-007's migration logic)
- [ ] `setup-proxy-negotiate.sh --remove` then performs the same Basic-mode teardown of `.profile`/apt/Docker/Podman
- [ ] `/etc/wsl-manager/proxy-mode` is deleted last, only on full success
- [ ] `/etc/krb5.conf` is **not** touched by teardown
- [ ] System packages `krb5-user` and `pipx` are **not** removed by teardown
- [ ] `docs/wsl-manager.md` documents Negotiate mode: when to pick it, the `kinit` prerequisite, troubleshooting (`klist`, `px --test`, restarting px)
- [ ] Pester unit tests cover the mode-marker dispatch branch
- [ ] All existing tests continue to pass
