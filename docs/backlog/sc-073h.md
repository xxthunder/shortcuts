# [SC-073h] update-scoop requirements

**Status**: In Progress
**Priority**: Medium
**Component**: `docs/requirements/update-scoop.md` (new), `docs/traceability/update-scoop.md` (new), `tools/scoop/update-scoop.ps1`, `lib/scoop/scoop.ps1` and their tests, `docs/runbooks/scoop-update.md`
**Depends on**: [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want update-scoop's current behaviour written down as requirement needs, traced to its code and tests, so that the second tool follows the pattern px-proxy set.

**Description**:
update-scoop is documented in `docs/runbooks/scoop-update.md`: an interactive, resilient loop that updates Scoop apps, run under Windows PowerShell 5.1 in a classic console so it can update pwsh and Windows Terminal. It is small, so it goes first and shows whether the px-proxy pattern carries over to a second tool unchanged.

**Scope Decisions**:
- **Requirements first, ubCode when it is ready** (author, 2026-11-14): this item does not wait for the rest of px-proxy (SC-073a, SC-073b, SC-073e, SC-073f). The only thing that waits is ubCode, which reads no PowerShell before its release with useblocks/ubcode#4750; the Sphinx build traces the markers with the codelinks pin of the day, and the ubCode comparison stays with [SC-073a](sc-073a.md). The pattern SC-073c settled (requirements by capability, markers on the functions and `It`s that implement and test them, ADRs that constrain them) is the one to copy.
- **Requirements are drafted by prompt and approved before anything is written**, as in [SC-073c](sc-073c.md): from what is true now, the code, its tests and the documentation; the Done items that touched the tool are hints, not a source. Behaviour that cannot be determined is listed in this item, not guessed.
- **Markers for its own requirements only**, as in SC-073c: the functions that implement a requirement and the `It`s that test it; the rest of the tool's functions wait for the check for unmarked functions in [SC-073e](sc-073e.md).
- **Requirement ID scheme**: `REQ_SCOOP_<TOPIC>`, as px-proxy's `REQ_PX_<TOPIC>`.
- **The requirements, approved** (author, 2026-11-14): drafted in the Q&A before the plan, so the loop writes exactly this text, ordered by capability.
  - *Start*
    - `REQ_SCOOP_PRESENT` **update-scoop needs Scoop**: without a `scoop` command it says "Scoop is not installed" and ends without touching anything.
    - `REQ_SCOOP_REFRESH_START` **Scoop is refreshed once at startup**: `scoop update` runs once before the first list; a failure is shown and the helper goes on.
  - *Menu*
    - `REQ_SCOOP_LIST` **the menu lists the apps that have updates**: numbered, each with its installed and latest version, read from `scoop status` in both its object and its text output. With none, it says "All apps are up to date!".
    - `REQ_SCOOP_SELECT` **the user picks apps by number, all, refresh or quit**: numbers separated by commas update those apps; `A` updates all, `R` refreshes, `Q` quits; letters in either case. With no updatable apps, only `R` and `Q` are offered. An invalid number or text is warned about and skipped, and the valid numbers of the same input still count. Nothing valid gives "No apps selected for update." and the menu again.
    - `REQ_SCOOP_UPDATE` **selected apps are updated one by one, each with its own result**: `scoop update <app>` per app, success or failure per app. Then it waits for a key, so the output can be read before the list is redrawn. A host without an interactive console does not fail.
    - `REQ_SCOOP_REFRESH` **`R` refreshes Scoop and checks again**.
  - *Resilience*
    - `REQ_SCOOP_LOOP` **only `Q` ends the session**: a failing Scoop command or an error in one round is shown, and the menu comes back.
  - *Console*
    - `REQ_SCOOP_CONSOLE` **update-scoop runs under Windows PowerShell 5.1 in a classic console**: `update-scoop.bat` opens it detached, in `conhost.exe` under `powershell.exe`, with the user profile loaded for the proxy. This is what lets it update `pwsh` and Windows Terminal. ADR-0001 constrains it.
  - *In CI and tests*
    - `REQ_SCOOP_CI` **without a console user it updates everything once**: in CI and tests it makes one update-all pass, with no prompt and no pause, and returns.
- **A requirement implemented in a wrapper names it** (author, 2026-11-14): `.bat` and `.cmd` wrappers carry no markers (SC-073), so `REQ_SCOOP_CONSOLE` names its wrapper in a field, `:implemented_in: tools/scoop/update-scoop.bat`, and the schema rule that every requirement is implemented accepts that field in place of a code trace.
- **Test titles with commas are renamed** (author, 2026-11-14): the schema forbids commas in test titles, so the `It`s that get a marker lose them, as in SC-073c.
- **ADR-0001's smoke guard stays untraced** (author, 2026-11-14): `test/bin/smoke-ps51.ps1` is no Pester test and has no result in `junit.xml`.
- **`REQ_SCOOP_CONSOLE` is tested by reading its wrapper** (the agent's call, not discussed): `tools/scoop/update-scoop.Tests.ps1` checks what `update-scoop.bat` starts (detached, `conhost.exe`, `powershell.exe`, `-File` with `%*`, the profile loaded), in a codelinks project of its own, `update-scoop-wrapper-tests`, since a project reads one directory.
- **px-proxy's traces page is filtered to its own needs** (the agent's call, not discussed): its tables select `REQ_PX` and `TEST_PX`, so a second tool's needs do not show there.
- **Open points** (2026-11-14), behaviour this item does not change:
  - Without Scoop, update-scoop ends with exit code 0, as `Invoke-ScoopUpdate` only returns; the runbook says it "exits with a message". `REQ_SCOOP_PRESENT` states what is true now.

**Acceptance Criteria**:
- [ ] `docs/requirements/update-scoop.md` states update-scoop's current behaviour as requirement needs, ordered by capability, approved by the author
- [ ] Every requirement is implemented and tested: a codelinks marker on a function and on a Pester `It` traces to it, and the documentation builds with Sphinx `-W`
- [ ] The ADRs that constrain update-scoop link the requirements they constrain
- [ ] update-scoop's documentation links its requirements and traces page, as px-proxy's runbook does
