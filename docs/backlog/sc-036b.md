# [SC-036b] ✅ DONE - Negotiate mode Phase 1 — bootstrap install of krb5 and px

**Status**: Done (2026-05-29)
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy-negotiate.sh`, `lib/wsl/proxy.ps1`
**Depends on**: [SC-036a](sc-036a.md)
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer picking Negotiate mode, I want the setup to install `krb5-user` and `px-proxy` through a temporary authenticated proxy so that the Kerberos tooling is available on disk before Kerberos is configured — without leaking Basic-auth credentials into any process environment.

**Description**:
Implements Phase 1 of the four-phase Negotiate workflow (see [SC-036](sc-036.md)). After this slice, `which px` and `which kinit` succeed inside the target distro; Kerberos is **not** yet configured and px is **not** yet running.

This phase has a chicken-and-egg problem: installing the Kerberos stack needs a working authenticated proxy, but the authenticating proxy (px) is what we are trying to install. Solution: temporarily point apt and pip at the company proxy with Basic-auth creds. The key security constraint (from the SC-036 threat model) is that Basic-auth credentials must **never be exported to the shell environment** — AI coding agents running in the same WSL session can read `/proc/*/environ` of any process owned by the same user.

**Credential handling during bootstrap**:
- **apt**: creds live in `/etc/apt/apt.conf.d/99proxy` (root-owned, 644). Same pattern as SC-007 Basic mode. apt reads its config; no env var needed.
- **pip/pipx**: write a temporary `~/.config/pip/pip.conf` with `[global] proxy = http://user:pass@host:port` before `pipx install px-proxy`, then delete `pip.conf` after the install succeeds. pip reads from config; no env var needed.
- **Never exported**: at no point does this script run `export HTTP_PROXY=...`. The Basic-auth URL does not enter any process env.

**Scope Decisions**:
- **Creds in config files only** (no `export HTTP_PROXY`): preserves the Negotiate threat model even during bootstrap. Cost: ~5 extra lines of shell to write + delete `pip.conf`.
- **Bootstrap URL via stdin, not cmdline**: the PS1 caller pipes the Basic-auth-embedded URL to the script's stdin (one line, consumed by `read -r BOOTSTRAP_PROXY_URL`). The script refuses to read from a TTY (`[ -t 0 ]`), so a missing pipe fails fast instead of blocking. Rejected alternative: passing the URL as `--bootstrap-proxy-url=...`. The whole point of Negotiate mode is to keep creds out of `/proc/<pid>/*` — env vars persist for every child shell, and cmdline persists for the script's lifetime. SC-007 accepts cmdline exposure because Basic mode also persists creds in env; Negotiate explicitly rejects that, so the bootstrap path stays consistent and uses neither.
- **`pipx`, not `pip3`**: Ubuntu 24.04+ enforces PEP 668; system-level `pip3 install` is blocked.
- **Marker transition**: write `negotiate-bootstrap` to `/etc/wsl-manager/proxy-mode` at the start of Phase 1 (not `negotiate` — full Negotiate state is reached only after SC-036d). SC-036e's `--remove` treats `negotiate-bootstrap` and `negotiate` identically for teardown purposes.
- **Stop before krb5.conf/px.ini**: this slice must not touch Kerberos config, must not start px, must not run `kinit`. Those belong to SC-036c.
- **Treat a 407 from `apt-get update` as a hard failure**: `apt-get update` exits 0 even when every source fails behind the proxy — failed fetches are only `W:` warnings ("ignored, or old ones used instead"). So a wrong bootstrap password yields a 407 that apt swallows, and the install step can still succeed offline when the packages are already cached/installed — a false success. Bootstrap captures the `apt-get update` output and aborts with exit 2 if it sees `Proxy Authentication Required` (or any non-zero exit). Found in UAT step 5: a deliberate cred typo reported success instead of exit 2.
- **Mode-aware PS1 success banner**: `Install-WslProxy` previously printed the Basic-mode target list (`~/.profile`, `~/.docker/config.json`, `~/.config/containers/containers.conf`) on every success, which is wrong for Negotiate bootstrap — Phase 1 touches none of those. The banner now branches on `$authMode`: Negotiate reports the installed tooling, the apt bootstrap config, the mode marker, the removed legacy block, and a note that Phases 2-4 are still pending. Found alongside UAT step 5.
- **Strip the legacy Basic-mode `.profile` block on migration**: a distro previously configured by SC-007 Basic mode carries `export http_proxy="http://user:pass@host:port"` inside the `# BEGIN/END wsl-manager proxy` block in `~/.profile` (and possibly `~/.bashrc`). Those creds are exported into every login shell and readable via `/proc/<pid>/environ` — exactly the leak Negotiate mode exists to close. Bootstrap removes that managed block up front (reusing the SC-007 markers + `sed` removal) so no Basic-auth creds linger in env during Phases 1-3. Cost: migrated tools relying on the env proxy have none until SC-036d rewrites the same block to `http://localhost:3128` — the same position a fresh distro is already in (fresh distros never had a `.profile` proxy block after Phase 1). This was found in UAT (step 3 failed on a migrated distro showing the old creds); without it the epic's "no creds in env" goal would not hold for migrated distros until Phase 4.
- **Idempotent re-run**: if re-invoked, re-read the Basic-auth creds via prompt, overwrite `apt.conf.d/99proxy`, re-run `apt install` (no-op if already installed), re-run `pipx install` (no-op if already installed), re-run `pipx ensurepath`.
- **Exit code 10 retired**: the SC-036a stub used exit 10 to signal "not yet implemented". With Phase 1 landing here and Phases 2-4 implementing the rest, exit 10 is no longer emitted; the corresponding handler in `Install-WslProxy` is removed.

**UAT Procedure** (run on a corporate WSL distro with the feature branch checked out):

1. [x] **Happy path**: `wsl-manager setup-proxy` → `A` (or `M`) → confirm/enter URL → auth `N` → enter bootstrap username/password. Expect: apt-get install completes, `pipx install px-proxy` completes, no errors.
2. [x] **End state**: after the script returns 0, verify
   - `cat /etc/wsl-manager/proxy-mode` prints `negotiate-bootstrap`
   - `ls -l ~/.local/bin/px` exists and is executable
   - `command -v kinit` resolves to `/usr/bin/kinit`
   - `cat /etc/apt/apt.conf.d/99proxy` shows the bootstrap URL with creds
   - `ls ~/.config/pip/pip.conf` returns "No such file or directory" (trap-deleted)
3. [x] **No env leakage**: open a new shell, run `env | grep -i proxy`. Expect: **nothing** — no proxy env vars at all. On a distro migrating from Basic mode, bootstrap strips the legacy `# BEGIN/END wsl-manager proxy` block from `~/.profile`/`~/.bashrc`, so the old `http://user:pass@...` exports are gone. (Phase 4 / SC-036d re-adds the block pointing at `http://localhost:3128`.) Confirm the block is gone: `sed -n '/# BEGIN wsl-manager proxy/,/# END wsl-manager proxy/p' ~/.profile` prints nothing.
4. [x] **Idempotent re-run**: run setup again, enter the same creds. Expect: `pipx install` is skipped with "px-proxy already installed (pipx list); skipping pipx install"; apt operations are no-ops; script still exits 0.
5. [x] **Cred typo**: re-run, enter wrong password. Expect: `apt-get update` emits `407 Proxy Authentication Required` warnings; the script detects the 407 in the captured output (apt itself exits 0 on failed fetches) and aborts with exit 2 — `[ERROR] apt-get update failed — proxy rejected the bootstrap credentials (HTTP 407)…`. The PS1 reports exit code 2; mode marker still reads `negotiate-bootstrap` so SC-036e teardown can later clean up. (Note: the script must abort here even on a re-run where krb5/px are already installed — otherwise verification passes against the prior install and the typo is masked.)
6. [x] **Empty username at prompt**: re-run, press Enter at the username prompt. Expect: PS1 throws "Bootstrap credentials are required for Negotiate mode setup."; no script invocation.
7. [x] **Direct shell invocation guard**: from inside the distro, run `bash lib/wsl/scripts/setup-proxy-negotiate.sh --proxy-url=http://x:1 --no-proxy=y --username=$USER` (no stdin pipe). Expect: error "Bootstrap proxy URL must be piped on stdin. Refusing to read from a terminal." and exit 4.
8. [x] **Regression — Basic mode**: full SC-007 happy path (`A`/`M` → `B` → creds). Expect: unchanged behavior; `/etc/wsl-manager/proxy-mode` reads `basic`.

**Technical Notes**:
- `pipx install px-proxy` pulls the `px-proxy` package; per the SC-036 `Verified` note, `px --test --auth=NEGOTIATE` passed on the user's system after this install, so no GSSAPI extras are required here.
- Suggested `pip.conf` writer:
  ```bash
  mkdir -p "$TARGET_HOME/.config/pip"
  cat > "$TARGET_HOME/.config/pip/pip.conf" <<EOF
  [global]
  proxy = $BASIC_PROXY_URL
  EOF
  trap 'rm -f "$TARGET_HOME/.config/pip/pip.conf"' EXIT
  ```
