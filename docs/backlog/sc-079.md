# [SC-079] Containers in a mirrored-mode distribution reach neither the proxy nor its CA

**Status**: In Progress
**Priority**: High
**Component**: `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/scripts/setup-ca.sh`, `docs/wsl-manager.md`
**Related**: [SC-061](sc-061.md) (setup-proxy and the Podman files it writes), [SC-066](sc-066.md) (wsl-manager hands the Linux side to Ansible)

**Summary**:
As a developer behind a TLS-inspecting corporate proxy, I want containers in my WSL distribution, devcontainers included, to reach the internet through the proxy and to trust its CA, so that builds and tools inside a container work like they do in the distribution itself.

**Description**:
Found on 2026-10-28 in a Debian 13 distribution with `networkingMode=mirrored`, rootless Podman 5.4 (network `pasta`), the proxy and CA set up by `setup-proxy` and `setup-ca`, and a DevPod workspace from `mcr.microsoft.com/devcontainers/base:debian`.

The distribution itself works, and so do image pulls: `setup-proxy` writes the proxy into `[engine] env` of `~/.config/containers/containers.conf`, and the Podman socket service uses it too. Inside a container, HTTPS fails, for two separate reasons:

1. **The proxy is out of reach.** Podman hands the proxy variables (`http_proxy=http://127.0.0.1:3128`) into the container, where `127.0.0.1` is the container's own loopback. In mirrored mode, port 3128 is the Windows loopback: the distribution reaches it, but neither `host.containers.internal` (169.254.1.2, pasta's address for the host) nor the distribution's LAN address does. With `--network=host`, the container reaches it.
2. **The proxy's CA is missing.** With `--network=host`, `curl -k https://github.com` gets 200, but without `-k` it fails the certificate check: the image trusts its own CA bundle, not the one `setup-ca` extends.

**Scope Decisions**:
- **wsl-manager, not the image or the project** (proposed by the agent): proxy and CA are a property of the machine, and `setup-proxy` and `setup-ca` already own them in the distribution; a devcontainer should not need to know them.
- **Containers keep their own network; pasta forwards the proxy port** (decided 2026-11-04): host networking (`netns = "host"`) is rejected. The containers on this machine are DevPod workspaces, Molecule tests, throwaway test containers and Structurizr; with host networking, `-p` mappings stop meaning anything, and Molecule instances that run the same service on the same port collide. Instead, `[network] pasta_options = ["-T", "<port>"]` makes pasta forward the container's `127.0.0.1:<port>` to the distribution's loopback, which in mirrored mode is the Windows loopback. The proxy variables Podman already hands in then work unchanged. The port comes from the proxy URL, and the option is written only when the proxy's host is a loopback address.
- **The CA comes in as a mount at a path of its own plus variables** (decided 2026-11-04, revised the same day): every container gets the distribution's bundle mounted read-only at `/etc/wsl-manager/ca-certificates.crt`, and `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS` and `PIP_CERT` point to it. The first decision mounted it over the image's own `/etc/ssl/certs/ca-certificates.crt`; that breaks `update-ca-certificates` in every container and every `podman build` (see Findings), and so every image that installs `ca-certificates`. The cost of the own path: a tool that reads only the system bundle and ignores the variables does not trust the proxy.
- **`containers.conf` is SC-061's, also on `--remove`** (decided 2026-11-04): "leave `containers.conf` alone" in the acceptance criteria means SC-079 adds no change to it. `setup-proxy --remove` deletes it as it did before; changing that is [SC-061](sc-061.md).
- **Each script writes its own drop-in file; `containers.conf` stays untouched** (decided 2026-11-04): `setup-proxy` writes the network setting to `~/.config/containers/containers.conf.d/wsl-manager-proxy.conf`, `setup-ca` writes the CA settings to `/etc/containers/containers.conf.d/wsl-manager-ca.conf`, and each one's `--remove` deletes its own file. This follows [ADR 0002](../architecture/adr/0002-wsl-manager-changes-only-what-it-marked.md) and needs nothing from [SC-061](sc-061.md); SC-061 can later move `[engine] env` into the same `wsl-manager-proxy.conf`.
- **The drop-ins append to lists, never replace them** (decided 2026-11-04): every list they set (`pasta_options`, `volumes`, `env`) ends with `{append=true}`, so lists the user keeps in their own `containers.conf` stay in force.
- **Not in scope**: Docker Engine, the JVM's trust store, and tools that read only the system bundle and ignore the variables (apt over HTTPS, for one). Each gets its own item when it is needed.

**Findings** (spike on 2026-11-04, the distribution from the Description, settings passed through `CONTAINERS_CONF_OVERRIDE` and a drop-in under a scratch `XDG_CONFIG_HOME`):
- Without the settings, a container's `curl` to the proxy fails with "Failed to connect to 127.0.0.1 port 3128"; with `--network pasta:-T,3128`, `curl -k https://github.com` gets 200.
- With all settings and no extra flags: `curl https://github.com` gets 200 in `mcr.microsoft.com/devcontainers/base:debian` and `base:ubuntu-24.04` and in a DevPod-built image; `apt-get update` works in `base:debian`; `npm view` works in `javascript-node:5-24-bookworm`, and fails without `NODE_EXTRA_CA_CERTS`; Python's `urllib` gets 200 in `geerlingguy/docker-debian13-ansible` (Molecule); `-p 18080:80` still serves.
- Rootless Podman 5.4 reads `~/.config/containers/containers.conf.d/` and `/etc/containers/containers.conf.d/`, and the `[engine] env` from `containers.conf` still applies next to a drop-in.
- A drop-in's plain `[containers] env` replaces the user's own `env` list; with `{append=true}` as the last element, both lists apply. The same holds for `volumes`.
- `[containers] volumes` applies to `podman build` as well. With the bundle mounted read-only over `/etc/ssl/certs/ca-certificates.crt`, `update-ca-certificates` fails in `podman run` and in a `RUN` step ("mv: cannot move 'ca-certificates.crt.new' to 'ca-certificates.crt': Device or resource busy"). Mounted at `/etc/wsl-manager/ca-certificates.crt`, `update-ca-certificates` exits 0 and `curl https://github.com` gets 200 through `SSL_CERT_FILE`.
- `podman build` gets the proxy and the mount but not `[containers] env`: in a `RUN` step, `curl https://github.com` fails the certificate check unless the Containerfile sets `SSL_CERT_FILE` itself.

**Acceptance Criteria**:
- [x] In a mirrored-mode distribution set up by wsl-manager, `podman run --rm mcr.microsoft.com/devcontainers/base:debian curl -sS https://github.com` succeeds without `-k` and without extra flags
- [x] `devpod up` with a plain devcontainer gives a workspace whose `curl https://github.com` succeeds
- [x] In the same distribution, `npm view` in `mcr.microsoft.com/devcontainers/javascript-node` succeeds, and a container started with `-p` serves on the published port
- [x] `setup-proxy --remove` and `setup-ca --remove` each delete their own drop-in file and leave `containers.conf` alone
- [x] `docs/wsl-manager.md` says what containers get and why
- [x] Unit tests cover the new configuration
