# [SC-073k] Two codelinks questions for useblocks: the Pester path of a test marker, markers in comment-based help

**Status**: Open
**Priority**: Low
**Component**: upstream: `packages/sphinx-codelinks/` in [useblocks/sphinx-needs](https://github.com/useblocks/sphinx-needs); `ubproject.toml`, the test markers in `tools/proxy/` and `lib/scoop/`

**Summary**:
As the maintainer, I want two open questions on PowerShell markers settled with useblocks, so that a test marker need not repeat its Pester path and the rule for markers in comment-based help is known.

**Description**:
Both questions came up in [SC-073a](sc-073a.md) and stayed open when useblocks released the PowerShell support (sphinx-codelinks 2.2.0, ubCode 0.40.0). The author moved them here on 2026-11-24, so that SC-073a can close with the pin move.

1. **The Pester path as a field.** A test result finds its test by matching the result's case name against the test's title (SC-073d). The title is the Pester path of the `It` (`Describe.Context.It`), so every test marker repeats a path that codelinks could read from the code. In 2.2.0 codelinks already knows the structure: an `It` is entity kind `test`, a `Describe` or `Context` is `namespace`. A field with the path would let the `join` match on it, and the marker's title could become free text.
2. **Markers in comment-based help.** useblocks decided that comment-based help first in a function's body documents that function (`doc_comment`). Still open: does a marker written inside a `.SYNOPSIS` block count as a marker of that function, or is it ignored?

**Scope Decisions**:
- **Moved out of SC-073a** (author, 2026-11-24): the questions do not block the pin move; SC-073a closes without them.

**Acceptance Criteria**:
- [ ] Both questions are raised with useblocks the way their `CONTRIBUTING.md` asks, and their answers are recorded here
- [ ] If useblocks adds a Pester path field: the test markers drop the repeated path, the `join` in `ubproject.toml` matches on the field, and the documentation builds with Sphinx `-W`
