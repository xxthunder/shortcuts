# [SC-058] ✅ DONE - Redraw the WSL Manager panel at the live console width after a resize

**Status**: Done (2026-09-20)
**Priority**: Medium
**Component**: `lib/wsl/manager.ps1`, `lib/wsl/commands.ps1`, `lib/wsl/manager.Tests.ps1`, `lib/wsl/commands.Tests.ps1`
**Related**: [SC-016c](sc-016c.md) (introduced the Spectre table), [SC-057](sc-057.md) (the redraw that exposed this), [SC-032](sc-032.md) (redraw on resize while the prompt is up)

**Summary**:
As a user who resizes the terminal while the manager is open, I want the next redraw to fill the new width cleanly, so that widening the window does not leave every line of the table split in two for the rest of the session.

**Description**:
`Show-WslDistroTable` and `Get-WslManagerPanel` render with `-Expand`, so the table and panel span the console. That is the wanted look. The defect: start the manager at N columns, widen the window, and select **Refresh list** (or any command). Every line of the panel is broken after N-1 characters, with the remainder on the next line, and every later redraw looks the same. Narrowing the window below N and redrawing makes it look right again. Observed 2026-09-16 at a 141-column start: at 213 columns each line split after 140 characters.

**Root cause** (established 2026-09-19 with the probes below): `pwsh -File wsl-manager.ps1` runs the whole script as one pipeline, so every object the manager emits reaches one `Out-Default`. `Start-InteractiveMode` emitted the panel renderable to the pipeline (`Get-WslManagerPanel -DistroContent $distroContent` on its own line). PowerShell's formatting engine then opens a format group for the renderable's type through PwshSpectreConsole's ps1xml `CustomControl` view and captures the column width once, at the first draw. The group stays open until an object of a different *formatted* type arrives; strings are written out-of-band and do not close it. The manager only ever emits panel renderables, so the width captured at the first draw wraps every later one. Spectre itself is not involved: the module re-reads `$Host.UI.RawUI.BufferSize.Width` on every write and rendered the correct width in every probe.

Ruled out along the way, each by a probe: a stale console width (all five width readings agreed with the window at every step, through `Clear-Host` and the `.bat` wrapper), `Read-SpectreSelection` (the split reproduces with `Read-Host`), `Clear-Host`, and the `cmd.exe`-started console.

**Probe evidence** (scratch scripts, each launched through a `.bat` like the manager):

| Probe | Draw path | Prompt | Result after widening |
|-------|-----------|--------|-----------------------|
| `probe` | table without `-Expand`, renderable to pipeline | `Read-SpectreSelection` | fine (content narrower than start width, nothing to wrap) |
| `probe-expand` | table with `-Expand`, renderable to pipeline | `Read-SpectreSelection` | split at start width minus 1; Spectre's widest line correct |
| `probe-wrap` | plain strings via pipeline, `Write-Host`, `[Console]::Out`, `$Host.UI`, `Out-Host` | `Read-Host` | none split |
| `probe-fmt` | renderable to pipeline, `Out-SpectreHost`, plain object via `Format-Custom` | `Read-Host` | none split (`Format-Custom` closed the group every iteration) |
| `probe-sel` | renderable to pipeline and `Out-SpectreHost` | `Read-SpectreSelection` | pipeline split, `Out-SpectreHost` fine |
| `probe-group` | renderable to pipeline only | `Read-Host` | split |

**Scope Decisions**:

- **Write the panel with `Out-SpectreHost`.** It renders the renderable to a string at the live console width and returns the string, which bypasses the format group. One pipe in `Start-InteractiveMode`; `Get-WslManagerPanel` keeps returning the renderable so its unit test stays a pure check of the panel options.
- **Keep `-Expand` on table and panel.** A content-sized render was tried on this branch as a mitigation and rejected: the wanted look is the table spanning the window. With the root cause fixed there is nothing left to mitigate.
- **Not in scope**: redrawing while the prompt is up, which needs a menu that owns its key loop ([SC-032](sc-032.md)); the CLI `list` command and `Select-WslDistro`, which draw once per process and cannot hit a stale group.

**Acceptance Criteria**:
- [x] `Start-InteractiveMode` pipes the panel through `Out-SpectreHost` instead of emitting it to the pipeline
- [x] `Show-WslDistroTable` and `Get-WslManagerPanel` keep `-Expand`
- [x] Unit test: `Start-InteractiveMode` invokes `Out-SpectreHost` exactly once per draw with the panel; the two `-Expand` assertions stay
- [x] All existing tests continue to pass
- [x] PSScriptAnalyzer is clean
- [x] UAT procedure below executed; all steps pass

   Expected: unchanged, still clean.

   Expected: clean again at the full width.
