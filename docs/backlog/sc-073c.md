# [SC-073c] px-proxy requirements, and the items and ADRs that change them

**Status**: In Progress
**Priority**: Medium
**Component**: `docs/requirements/px-proxy.md` (new), `docs/backlog/`, `docs/architecture/adr/`
**Depends on**: [SC-073b](sc-073b.md); XAS-044b, XAS-044c and XAS-044d in xxthunder-agentic-skills

**Summary**:
As the maintainer, I want px-proxy's current behaviour written down as requirement needs, with every closed px-proxy item and ADR 0005 linked to the requirements they changed, so that the history of px-proxy reads as changes to a current state.

**Description**:
The requirements are bootstrapped with the read-only scan of XAS-044d from what is true now: `tools/proxy/px-proxy.ps1`, its tests and `docs/runbooks/px-proxy.md`. The scan then maps the closed items that touched px-proxy (listed in [SC-073](sc-073.md)) onto them. The author approves both before anything is written.

The whole backlog and all ADRs move to need headers in one migration (XAS-044b); only the px-proxy items get their requirements links in this item.

**Scope Decisions**:
- **Requirement ID scheme**: `REQ_PX_<TOPIC>`, decided with the first requirements (2026-10-24).
- **Thin slice first** (author, 2026-10-24): three requirements (`REQ_PX_FILES`, `REQ_PX_UPSTREAM`, `REQ_PX_REMOVE`) come with the first pull request of SC-073b, so the codelinks pull request (SC-073a) can link a published example. They were drafted from the code, the tests and the runbook and approved by the author, not bootstrapped by the XAS-044d scan; the scan and the item links follow in this item.
- **A mapping the scan cannot determine** is listed in this item, not guessed.
- **ADR 0005** links the requirements it constrains; its context item ([SC-067](sc-067.md)) becomes a link to the story need.

**Acceptance Criteria**:
- [ ] `docs/requirements/px-proxy.md` states px-proxy's current behaviour as requirement needs, approved by the author
- [ ] All items and ADRs carry need headers; `backlog.py check` reports nothing
- [ ] Every closed px-proxy item names the requirements it changed, or that it changed none; undetermined ones are listed here
- [ ] ADR 0005 links the requirements it constrains
- [ ] ubCode and the Sphinx build show the same story-to-requirement traces
