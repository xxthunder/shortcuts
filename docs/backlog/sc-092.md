# [SC-092] px falls back to the setup script when Windows auto-detect finds no proxy (upstream PR)

**Status**: In Progress
**Priority**: Low
**Component**: [genotrance/px](https://github.com/genotrance/px) `px/wproxy.py` and its tests (upstream, via a fork)

**Summary**:
As a px user whose Windows proxy settings have both "Automatically detect settings" and a setup script on, I want px to fall back to the setup script when WPAD finds nothing, as the browser does, so that px does not connect directly and fail where a firewall blocks direct connections.

**Description**:
SC-091 found the gap and documented it in the runbook. px 0.13.1 (`px/wproxy.py`, `Wproxy.__init__` on Windows) takes exactly one mode from `WinHttpGetIEProxyConfigForCurrentUser`: `fAutoDetect` gives `MODE_AUTO`, and the setup-script URL (`lpszAutoConfigUrl`) is then dropped. In `MODE_AUTO`, `winhttp_find_proxy_for_url` calls `WinHttpGetProxyForUrl` with `WINHTTP_AUTOPROXY_AUTO_DETECT` only. When WPAD fails (`ERROR_WINHTTP_AUTODETECTION_FAILED`, 12180), px returns `DIRECT`. WinINet, and so the browser, falls back to the setup script in that case.

The fix: when auto-detect is on and a setup-script URL is set, keep the URL and pass both flags (`WINHTTP_AUTOPROXY_AUTO_DETECT | WINHTTP_AUTOPROXY_CONFIG_URL`) with the URL in `lpszAutoConfigUrl`; WinHTTP then tries auto-detection first and uses the setup script when it fails. A probe with ctypes on the author's machine at headquarters on 2026-11-16 confirmed it for `https://www.google.com`: `AUTO_DETECT` alone failed with 12180, `CONFIG_URL` alone and both flags together returned the company proxy.

px master (`devel`) has the same `wproxy.py` as 0.13.1, and no px issue covers this. px is MIT-licensed; its CI (`.github/workflows/ci.yml`) runs pytest on Ubuntu and Windows on every pull request.

**Scope Decisions**:
- **Upstream, not a local patch** (the maintainer's call, 2026-11-16): px-proxy installs px unchanged; the fix goes to genotrance/px through a fork and a pull request. px-proxy needs no change and does not wait for the release.
- **Text posted under the author's name is a draft first**: the pull request's title and body are shown to the author and posted after a go.

**Acceptance Criteria**:
- [ ] With auto-detect on and a setup-script URL set, px's Windows proxy lookup passes both flags and the URL, so a failed WPAD falls back to the setup script.
- [ ] With auto-detect on and no setup-script URL, px behaves as before.
- [ ] Unit tests in px cover both cases, with the Windows API mocked.
- [ ] px's local checks that run on this machine pass; px's CI on the pull request is green.
- [ ] A pull request to genotrance/px is open, its text approved by the author before posting.
