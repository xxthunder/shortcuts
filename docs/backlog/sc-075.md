# [SC-075] CI on Node 24 actions, Python toolchain past the emSign CA incident

**Status**: Open
**Priority**: High
**Component**: `.github/workflows/test.yml`, `.github/workflows/claude.yml`, `pyproject.toml`, `uv.lock`, `.python-version`
**Related**: [SC-073d](sc-073d.md) (the run that showed the warning)

**Summary**:
As the maintainer, I want every CI action on a supported Node runtime and the Python toolchain past the emSign CA incident, so that the pipeline runs on maintained, trusted components.

**Description**:
Two security-related updates, raised on 2026-10-27:

- **Node 20 is deprecated on GitHub's runners.** The test job warns: "The following actions target Node.js 20 but are being forced to run on Node.js 24: actions/github-script". The action comes in through `codecov/codecov-action@v5`, used twice in the test job; the latest release is v7.1.1. `claude.yml` still uses `actions/checkout@v4`, where `test.yml` uses v7.
- **The eMudhra/emSign CA incident** (Python Software Foundation advisory, about 2026-10-20): the emSign root is removed from CA bundles; the advisory asks for at least certifi 2026.10.19, pip 26.2.2, uv 0.13.4, and Python 3.13.17 for the 3.13 line. `uv.lock` already holds certifi 2026.10.23. The documentation job installs uv through `astral-sh/setup-uv@v10.3.2` and Python through `.python-version` (`3.13`); which versions a run actually gets is not pinned.

The dev VM's own uv (0.12.4 on 2026-10-27) is set up by its provisioning, not by this repository; it is tracked there.

**Scope Decisions**:
- **Actions to their current major**: `codecov/codecov-action` to v7, `actions/checkout` in `claude.yml` to the version `test.yml` uses. Other actions only where they also warn.
- **Pin what the advisory names**: the uv version `setup-uv` installs and the Python patch level, so a run cannot fall back below the fixed versions.

**Acceptance Criteria**:
- [ ] A CI run on develop shows no Node 20 deprecation warning
- [ ] The documentation job runs uv 0.13.4 or later and Python 3.13.17 or later, stated in the repository rather than taken from whatever is latest
- [ ] `uv.lock` holds certifi 2026.10.19 or later
