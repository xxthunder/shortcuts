# [SC-086] ✅ DONE - Replace Keypirinha with PowerToys Command Palette on Alt+Space

**Status**: Done (2026-11-08)
**Priority**: High
**Component**: `scoop_mandatory.json`, `bin/install.ps1`, `config/keypirinha/`, `docs/index.md`, `docs/architecture/workspace.dsl`, `docs/architecture/workspace.json`
**Related**: [SC-070](sc-070.md) (Command Palette trial), CmdPal.Extension.Folders [CPF-002](https://github.com/xxthunder/CmdPal.Extension.Folders/blob/develop/docs/backlog/cpf-002.md) (extension that catalogs the shortcuts folders)

**Summary**:
As a keyboard-driven Windows user, I want the install to set up PowerToys Command Palette on `Alt+Space` instead of Keypirinha, so that I use Command Palette every day and test it thoroughly before deciding on a successor.

**Description**:
The trial SC-070 shows that Command Palette covers apps, `.url` files in the Start menu, Google, Everything (through an extension) and history ranking, but cannot catalog the shortcuts folders without an extension of its own; that extension is being built in CmdPal.Extension.Folders (CPF-002). To test Command Palette in daily use, the repository installs it instead of asking for a manual setup on every machine.

The first version installed Command Palette next to Keypirinha, on its default `Win+Alt+Space`. On 2026-11-08 the author changed the item: Keypirinha is no longer installed, and Command Palette takes over `Alt+Space`.

Raised on 2026-11-07.

**Scope Decisions**:
- **Integration before the trial closes** (the author's exception, 2026-11-07): SC-070 planned the integration only after a passing trial. The author integrates now to test Command Palette more thoroughly; SC-070 stays open for the verdict.
- **Parallel, not replacing** (2026-11-07, superseded on 2026-11-08): Keypirinha, its profile and its hotkey stay as they are.
- **Default hotkey** (2026-11-07, superseded on 2026-11-08): Command Palette is not configured; `Win+Alt+Space` is its default.
- **Keypirinha is not installed** (the author, 2026-11-08): `scoop_mandatory.json` drops `keypirinha`; the install neither copies its profile nor starts it; `config/keypirinha/` goes, since nothing reads it any more. A machine that has Keypirinha keeps it until the user runs `scoop uninstall keypirinha`; the user guide says so.
- **Command Palette on `Alt+Space`** (the author, 2026-11-08): the install sets Command Palette's activation shortcut to `Alt+Space` in its settings file.
- **The main block of `bin/install.ps1` is tested** (the author, 2026-11-08): its body moves into a function with unit tests, so that every changed line of the install sequence is covered; `codecov/patch` required it for the call of `Start-Launcher`.
- **Every mention of Keypirinha goes** (the author, 2026-11-08): besides the install, `docs/index.md` and the model, the rules in `AGENTS.md`, the skills in `.claude/skills/`, the catalog-refresh hints the tools print, the other docs and runbooks and `.vscode/settings.json` drop Keypirinha or name Command Palette. The skill `keypirinha-shortcuts` becomes a skill for the `.url` links that names no launcher. Reason: nothing should describe a launcher the install no longer sets up.
- **Where the hotkey lives** (from the PowerToys source, 2026-11-08): Command Palette is a packaged app; its settings are `%LOCALAPPDATA%\Packages\Microsoft.CommandPalette_8wekyb3d8bbwe\LocalState\settings.json` (`Utilities.BaseSettingsPath`, package identity `Microsoft.CommandPalette`). The activation shortcut is the key `Hotkey` with `win`, `ctrl`, `alt`, `shift`, `code` and `key` (`SettingsModel`, `HotkeySettings`); `Alt+Space` is `alt: true`, `code: 32`, `key: ""`, the others `false`. The install merges this key into the file and keeps every other setting; a running Command Palette picks it up after a restart.
- **The folder extension is not part of this item**: installing CmdPal.Extension.Folders follows once CPF-002 delivers it. Until then the scripts and links of the shortcuts folders are not in the launcher's catalog.
