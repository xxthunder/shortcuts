# [SC-091] The px-proxy runbook explains a 504 on site caused by the Windows proxy settings

**Status**: In Progress
**Priority**: Low
**Component**: `docs/runbooks/px-proxy.md`

**Summary**:
As a user whose tools get `504 Gateway Timeout` through px on a company site, I want the runbook to tell me which Windows proxy settings cause it and what to do, so that I fix the settings instead of pinning an upstream or rolling px-proxy back.

**Description**:
Since SC-087, px without `-ProxyHost` takes the upstream from the Windows proxy settings. On 2026-11-16 the author got `504 Gateway Timeout` through px at headquarters (wired, no VPN) and rolled px-proxy back to the version that pins the upstream. The cause was the Windows settings, not px-proxy:

- **Auto-detect on**: the author had ticked "Automatically detect settings" by hand. px 0.13.1 (`px/wproxy.py`) then uses WPAD only and ignores the PAC URL. `wpad` does not resolve at headquarters, so px logs "Autodetection failed, trying DIRECT instead", connects directly, and the firewall drops the connection after 20 seconds. Browsers keep working because WinINet falls back to the PAC URL; px does not.
- **Everything off**: sometimes the proxy settings from group policy are missing entirely. Then Windows names no proxy, px connects directly, and the browser fails as well. This is a problem for IT, not for px.

With the settings that group policy intends (PAC URL only, auto-detect off), px without an upstream works at headquarters: on 2026-11-16 it took `osde01proxy02.marquardt.de:8080` from the PAC, authenticated with Kerberos and got `200 Connection established`.

**Scope Decisions**:
- **No code change** (the maintainer's call, 2026-11-16): auto-detect is not meant to be on, so px-proxy keeps taking the upstream from Windows as SC-087 decided. The missing WPAD-to-PAC fallback in px is not reported upstream for now.

**Acceptance Criteria**:
- [ ] The runbook's Troubleshooting has a section for `504 Gateway Timeout` on site: check Internet Options (auto-detect off, the PAC URL set); with all settings missing, run `gpupdate /force` or contact IT; `-ProxyHost` as the stopgap.
- [ ] "How discovery works" says that px uses WPAD only when "Automatically detect settings" is on, and then ignores the PAC URL.
- [ ] `uv run poe docs` passes.
