# [SC-035] ✅ DONE - Add sync-ssh-config command for Windows DevPod access

**Status**: Done (2026-04-09)
**Priority**: High
**Component**: `lib/wsl/devpod.ps1`, `lib/wsl/devpod.Tests.ps1`, `lib/wsl/scripts/sync-ssh-config.sh`, `lib/wsl/manager.ps1`, `lib/wsl/manager.Tests.ps1`, `docs/wsl-manager.md`
**Depends on**: [SC-026](sc-026.md)

**Summary**:
As a developer using DevPod in WSL, I want a WSL Manager command that syncs SSH configuration between Windows and WSL — copying keys and known_hosts into the distribution, syncing DevPod SSH config blocks to Windows (with adapted ProxyCommand), and syncing non-DevPod config from Windows into WSL — so that I can connect to DevPod containers from Windows-side editors (VS Code, JetBrains) without manual SSH setup.

**Description**:
The current walkthrough recommends `core.sshCommand = ssh.exe` for git in WSL, which breaks DevPod because DevPod needs Linux-native SSH. Three things are needed:

1. **SSH keys and known_hosts in WSL**: Copy all private/public key pairs from `%USERPROFILE%\.ssh\` into the WSL distribution's `~/.ssh/` with correct permissions (`chmod 600` for private keys, `chmod 644` for public keys). Also copy `known_hosts` and `known_hosts.old` so the WSL environment trusts the same hosts as Windows.

2. **Sync non-DevPod SSH config from Windows into WSL**: Non-DevPod entries from the Windows-side `~/.ssh/config` are synced into the WSL `~/.ssh/config`, preserving any existing DevPod blocks in the WSL config.

3. **Sync DevPod SSH config blocks to Windows**: DevPod generates SSH config blocks in the WSL user's `~/.ssh/config` like this:

```
# DevPod Start hello-python.devpod
Host hello-python.devpod
  ForwardAgent yes
  LogLevel error
  StrictHostKeyChecking no
  UserKnownHostsFile /dev/null
  HostKeyAlgorithms rsa-sha2-256,rsa-sha2-512,ssh-rsa
  ProxyCommand "/usr/local/bin/devpod" ssh --stdio --context default --user vscode hello-python
  User vscode
# DevPod End hello-python.devpod
```

The script reads the WSL-side `~/.ssh/config` (source), extracts all `# DevPod Start ... # DevPod End` blocks, adapts the ProxyCommand to route through `wsl.exe`, and writes them to the Windows-side target config. This is a **sync operation**:

- DevPod blocks in the source are copied to the target with adapted ProxyCommand
- DevPod blocks in the target that have no counterpart in the source are **removed**
- Non-DevPod entries in the target are preserved untouched

The adapted ProxyCommand wraps the original command with `wsl.exe -d <distro> --`:

```
# WSL source:
ProxyCommand "/usr/local/bin/devpod" ssh --stdio --context default --user vscode hello-python

# Windows target:
ProxyCommand wsl.exe -d <distro> -- "/usr/local/bin/devpod" ssh --stdio --context default --user vscode hello-python
```

The TUI menu entry is **"Sync SSH Config"**. The command name is `sync-ssh-config`. It is a separate, independently re-runnable action.

### Technical approach

- **New shell script** `lib/wsl/scripts/sync-ssh-config.sh`:
  - Takes `--ssh-target-dir=<path>` argument (the Windows `.ssh` folder path in WSL mount form, e.g., `/mnt/c/Users/<user>/.ssh`) and `--distro-name=<name>` argument
  - **Key copy**: Copies all key pairs (`id_*`, `*.pub`) from the Windows `.ssh` dir into `~/.ssh/` in WSL; sets permissions: `chmod 700 ~/.ssh`, `chmod 600` private keys, `chmod 644` public keys
  - **known_hosts copy**: Copies `known_hosts` and `known_hosts.old` from the Windows `.ssh` dir into `~/.ssh/` in WSL with `chmod 644` permissions
  - **Config sync (Windows → WSL)**: Reads the Windows-side config, extracts non-DevPod entries, and syncs them into the WSL `~/.ssh/config` while preserving existing DevPod blocks
  - **Config sync (WSL → Windows)**: Reads `~/.ssh/config` (source), extracts all `# DevPod Start <name> ... # DevPod End <name>` blocks, adapts each ProxyCommand to prepend `wsl.exe -d <distro> --`, then writes all adapted blocks to `<target-dir>/config` replacing any existing DevPod blocks while preserving all non-DevPod entries
  - **Cleanup**: Any DevPod block in the target that has no matching block in the source is removed
  - **Backups**: Creates timestamped backups before modifying any config file
  - Is idempotent: safe to re-run; produces the same result regardless of prior state

- **New PowerShell function** `Invoke-WslSyncSshConfig` in `devpod.ps1`:
  - Validates distribution exists and DevPod is installed
  - Resolves the Windows user's `.ssh` path
  - Calls the shell script via `Invoke-WslDistroScript`
  - Follows existing patterns from `Install-WslDevPod`

- **Manager integration** in `manager.ps1`:
