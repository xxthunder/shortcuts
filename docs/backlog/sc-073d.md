# [SC-073d] Pester test results as needs

**Status**: Open
**Priority**: Medium
**Component**: `test/bin/testrunner.ps1`, `test/bin/testrunner.Tests.ps1`, `tools/proxy/px-proxy.Tests.ps1`, `ubproject.toml`
**Depends on**: [SC-073b](sc-073b.md), [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want every Pester test case to link the requirements it verifies in the JUnit report, so that both readers show each requirement with the result of its tests.

**Description**:
ubCode (since 0.37.0, beta) and sphinx-test-reports 3.x read JUnit XML directly: the `test-file` directive and its siblings, configured in the `[test_reports]` section of `ubproject.toml`. A `<property>` on a test case becomes a link through `property_link_types`; a value such as `REQ_1, REQ_2` gives one link per ID.

Pester cannot write such a property. Its JUnit writer (`TestResults.JUnit4.ps1`) puts properties only on a `<testsuite>`, for environment data; a `<testcase>` gets its full path as `name`, a status, a class name and a time, and no tags.

**Scope Decisions**:
- **The requirement ID is a Pester tag** on the test: `It '...' -Tag 'REQ_...'`.
- **`testrunner.ps1` adds the property**: after the Pester run, it writes each test's requirement tags into its test case in `test/out/junit.xml`, as one property the `[test_reports]` mapping links. It has every result object from the run.
- **Only requirement tags**: tags such as `Unit` and `Integration` (the runner's filter) stay out; the requirement ID pattern of SC-073c tells them apart.
- **Not pursued now**: test-case properties in Pester's own JUnit writer, as an upstream contribution.

**Acceptance Criteria**:
- [ ] `test/out/junit.xml` carries each test's requirement tags as a property of its test case; Pester tests cover the writer, including a test without requirement tags
- [ ] The px-proxy tests are tagged with the requirements they verify
- [ ] Each px-proxy requirement shows at least one test case with its result, in ubCode and in the Sphinx build
- [ ] A px-proxy requirement without a test case fails the documentation build
