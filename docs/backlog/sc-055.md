# [SC-055] Open a terminal in an installed distribution from wsl-manager

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/commands.ps1`, `lib/wsl/manager.ps1`, `lib/wsl/ops.ps1`, `tools/wsl-manager/wsl-manager.ps1`, `docs/wsl-manager.md`
**Related**: [SC-016](sc-016.md) (TUI modernization; reuses the SC-016d distro picker), [SC-031](sc-031.md) (grouped menu layout; this command needs a home in the regrouped menu)

**Summary**:
As a WSL Manager user, I want to open a shell in one of my installed distributions straight from the manager, so that after installing, cloning or configuring a distribution I can start using it without leaving the tool and typing `wsl.exe --distribution <name>` by hand.

**Description**:
Every workflow in the manager ends with a hint such as `To start: wsl.exe --distribution <name>` (`lib/wsl/install.ps1:139`, `lib/wsl/ops.ps1:142`, `lib/wsl/docker.ps1:296`), and the user has to copy that into another terminal. The manager already knows the distribution list and, since SC-016d, has an arrow-key picker for it; opening the shell is the obvious missing action.

The command opens the shell **next to** the manager, not in place of it: a new Windows Terminal tab when the manager itself runs inside Windows Terminal, otherwise a new console window. The manager stays open, so the user can open several distributions in turn or keep managing while the shell runs.

### Behaviour

- **TUI**: a new menu entry **Open terminal in distribution** uses `Select-WslDistro` (with its **Back to main menu** entry) and then launches the shell for the chosen distribution.
- **CLI**: `wsl-manager.ps1 shell <name>` launches directly; `wsl-manager.ps1 shell` without a name uses the picker interactively and warns "Provide -Name" in CI, exactly like the other commands.
- **Launch**: the shell starts as the distribution's default user in its home directory (`wsl.exe --distribution <name> --cd ~`). A stopped distribution is started by `wsl.exe` as a side effect; no separate start step.
- **Host detection**: when `$env:WT_SESSION` is set, the manager runs under Windows Terminal and opens the shell as a new tab in the same window (`wt.exe -w 0 new-tab wsl.exe --distribution <name> --cd ~`). Otherwise it opens a new console window (`Start-Process wsl.exe -ArgumentList "--distribution <name> --cd ~"`). Both are fire-and-forget; the manager does not wait for the shell to exit.
- **Feedback**: `==> Opened terminal for <name>` is printed, and the TUI returns to the menu without the "Press Enter to continue" pause (there is nothing to read).

**Scope Decisions**:

- **New tab beside the manager, not inline.** Decided at refinement (2026-09-12). Inline (`wsl.exe` in the foreground until `exit`) would need no `wt.exe`, but blocks the manager while the shell is open; a separate window in all cases ignores the Windows Terminal host most users run in. The tab is the natural fit, with the plain window as the fallback when there is no Windows Terminal to attach to.
- **Launching lives in `lib/wsl/ops.ps1` as `Open-WslDistroShell`**, alongside the other distribution operations; the TUI/CLI wiring is a thin `Invoke-OpenDistroShell` in `commands.ps1` following the `Invoke-RemoveDistro` shape (`Select-WslDistro`, then the op). The launcher is independently useful (a future Keypirinha link per distribution could call it), so it must not be buried in the command layer.
- **Detection by `WT_SESSION`, not by probing `wt.exe`.** The question is "is *this* console a Windows Terminal tab", which the environment variable answers; whether `wt.exe` exists on `PATH` does not. If `WT_SESSION` is set but `wt.exe` cannot be started, the error is surfaced rather than silently falling back.
- **`-w 0` targets the current window.** A new tab in the window the manager runs in is what the user expects; a fresh Windows Terminal window would be the `Start-Process` fallback in disguise.
- **Home directory via `--cd ~`.** Without it `wsl.exe` maps the manager's Windows working directory, which is meaningless for a distribution shell.
- **Skipping the pause reuses `$script:WslSkipContinuePause`** (same semantics: reset by `Start-InteractiveMode` before each command, honoured after it). The picker sets it on **Back to main menu**, a denied confirmation sets it ([SC-016e](sc-016e.md), which renames it from `$script:WslPickerWentBack`), and this command sets it after a successful launch.
- **Not in scope**: choosing the user (`--user`), a start directory other than home, running a command instead of a login shell, and Windows Terminal profiles per distribution. Each is a separate item if wanted.

**Acceptance Criteria**:
- [ ] `Open-WslDistroShell -Name <name>` in `lib/wsl/ops.ps1` validates the distribution with `Assert-WslDistroExists`, then launches `wsl.exe --distribution <name> --cd ~`
- [ ] When `$env:WT_SESSION` is set, the launch goes through `wt.exe -w 0 new-tab ...`; otherwise through `Start-Process wsl.exe`
- [ ] The launch is fire-and-forget: the function returns as soon as the tab or window is spawned
- [ ] `Invoke-OpenDistroShell` in `commands.ps1` uses `Select-WslDistro` when no name is given and returns quietly on `$null` (cancel, back, or CI warning)
- [ ] `Invoke-WslCommand` dispatches `shell`; `Invoke-WslManager` accepts `shell` in its `ValidateSet`
- [ ] The TUI menu shows **Open terminal in distribution**; after a launch, `==> Opened terminal for <name>` is printed and the menu returns without the "Press Enter to continue" pause
- [ ] After a successful launch `$script:WslSkipContinuePause` is set, so the TUI returns to the menu without pausing
- [ ] Unit tests cover: WT tab path, plain-window path, unknown distribution, CLI with name, TUI via picker, picker cancel, CI without name (both launchers mocked; no real `wt.exe` or `wsl.exe` is invoked)
- [ ] `docs/wsl-manager.md` documents the command (TUI and CLI) and the tab-versus-window behaviour
- [ ] The `To start:` hints in `install.ps1`, `ops.ps1` and `docker.ps1` mention the new command
- [ ] All existing tests continue to pass
- [ ] UAT procedure below executed; all steps pass

### UAT Procedure

1. In Windows Terminal, run `tools\wsl-manager\wsl-manager.bat`, select **Open terminal in distribution**, pick a stopped distribution. Expected: a new tab opens in the same window with a shell in that distribution's home directory, as its default user; the manager tab shows `==> Opened terminal for <name>` and is back at the menu with no pause.
2. Repeat for a running distribution. Expected: same result.
3. Pick **Back to main menu** in the picker. Expected: straight back to the menu, no tab opened.
4. From a classic console (`conhost.exe pwsh`, so `WT_SESSION` is unset), run `pwsh -File tools\wsl-manager\wsl-manager.ps1 shell <name>`. Expected: a new console window with the shell; the command returns immediately.
5. `pwsh -File tools\wsl-manager\wsl-manager.ps1 shell NoSuchDistro`. Expected: the "does not exist" error listing installed distributions; nothing opens.
6. `$env:CI = 1; pwsh -File tools\wsl-manager\wsl-manager.ps1 shell` (no name). Expected: the "Provide -Name" warning; nothing opens. Then `Remove-Item Env:CI`.
