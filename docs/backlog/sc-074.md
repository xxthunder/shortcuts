# [SC-074] ✅ DONE - README as landing page, the documentation on GitHub Pages

**Status**: Done (2026-10-25)
**Priority**: Medium
**Component**: `README.md`, `docs/index.md`, every Markdown file under `docs/`, `docs/_static/shortcuts.css` (new), `ubproject.toml`, `conf.py`, `AGENTS.md`
**Related**: [SC-073b](sc-073b.md) (documentation build and GitHub Pages), [SC-073c](sc-073c.md) (px-proxy requirements), [SC-004](sc-004.md) (made every document reachable from the README)

**Summary**:
As a user, I want the README to show the logo, the badges and a link to the published documentation, and everything else in the documentation on GitHub Pages, so that there is one place to read about shortcuts, built and checked like the requirements.

**Description**:
SC-073b publishes a Sphinx build on GitHub Pages, but the build holds only the px-proxy requirements and their traces. The user guide lives in `README.md`; the tool documents, the ADRs and the backlog are readable only on GitHub. This item moves the user guide from the README to `docs/index.md` and takes the whole `docs/` tree into the build.

A trial build of all of `docs/` on `develop` (2026-10-24) shows what Sphinx with `-W` asks for:

- **Every document in a toctree** (119 warnings): `docs/index.md` takes the tools and the development documents, `docs/architecture/README.md` the ADRs, `docs/backlog/README.md` the items, and the px-proxy runbook its requirements and traceability pages.
- **Heading anchors** (67 warnings): links to headings such as `#quick-start`, most of them in `wsl-manager.md`, need MyST heading anchors. MyST builds GitHub's slugs, so a link works on GitHub and in the build alike.
- **No link into `README.md`** (7 documents): the "Back to README" links at the top and bottom of a document point outside the build.
- **No skipped heading level** (69 warnings in 29 backlog items): their sub-headings are `###` directly below the `#` title.

**Scope Decisions**:
- **The README holds the logo, the tagline, the badges and the link to the documentation, nothing else** (author, 2026-10-24). Installation, usage, troubleshooting and the development section move to `docs/index.md`; only their links change, and the README's table of contents and section rules give way to the theme's page navigation.
- **The whole `docs/` tree is in the build** (author, 2026-10-24). This replaces "the document set grows with the slices" of SC-073b. The md parser's `include` in `ubproject.toml` names it, and `conf.py` keeps reading `include_patterns` from there. Markdown outside `docs/` stays out: agent instructions, skills and `tools/pslib/wsl/obsolete.md`.
- **px-proxy's documentation is its runbook, with the requirements and the traceability as pages below it** (author, 2026-10-24). `docs/requirements/px-proxy.md` and `docs/traceability/px-proxy.md` stay files of their own; the runbook's toctree puts them below px-proxy in the published documentation. The next tool with requirements follows the same pattern.
- **A documentation badge** (author, 2026-10-24) joins the README badges. It shows the state of the latest GitHub Pages deployment (shields.io `github/deployments`, environment `github-pages`) and links to the documentation (the agent's call).
- **A tool's documentation is titled with the tool's name** (author, 2026-10-25): the runbooks are titled `px-proxy` and `update-scoop`, the names of the scripts, so the sidebar's Tools list the tools rather than runbooks. The start page's links use the same names.
- **"Back to README" links are removed, not repointed**: the published documentation has the theme's navigation, and on GitHub the README is one click away. "Back to Backlog" and "Back to Architecture" stay; they point inside `docs/`.
- **Skipped heading levels in backlog items are fixed in the items, not suppressed in `conf.py`**, so that `-W` stays a gate for every document. Only the heading levels change.
- **The backlog items join through a hidden glob toctree** in `docs/backlog/README.md`, below the table of contents, which `backlog.py toc` rewrites and must not hold it.
- **Checkboxes render as checkboxes** (MyST `tasklist`), and the theme's sidebar shows the logo (the agent's call).
- **furo stays the theme, and needs are readable in its dark mode** (author, 2026-10-24, after the published requirements were unreadable in dark mode): sphinx-needs draws needs in the fixed light colours of its `modern.css`, while furo follows the colour scheme. `docs/_static/shortcuts.css` sets sphinx-needs' `--sn-color-*` tokens for furo's dark mode, chosen with the toggle or inherited from the system, as sphinx-needs' own documentation on furo does (`docs-theme/static/ub-furo.css` in useblocks/sphinx-needs). Every theme with a dark mode needs this mapping.
- **The content column grows with the window** (author, 2026-10-24): furo keeps it at 46em, centred. From the width at which the sidebar shows (63em), it takes the room up to the page's table of contents, up to 70em of text, and stays centred: the sidebar shrinks as the column grows.
- **The sidebar logo follows the colour scheme**: the title logo's letters are transparent and vanish on a dark background, so dark mode shows the icon and the name as text (the agent's call).
- **`AGENTS.md` and `docs/development-principles.md`** name `docs/index.md` where they named the README as the user documentation.
