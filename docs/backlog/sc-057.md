# [SC-057] Refresh the distribution list in the WSL Manager menu

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/manager.ps1`, `lib/wsl/manager.Tests.ps1`, `docs/wsl-manager.md`
**Related**: [SC-055](sc-055.md) (Start distribution makes the staleness visible), [SC-032](sc-032.md) (why a live-updating table is not an option)

**Summary**:
As a WSL Manager user, I want the distribution table above the menu to show the current state of my distributions, so that after starting or stopping one I am not looking at "Stopped" next to a distribution whose shell is open in the next tab.

**Description**:
`Start-InteractiveMode` (`lib/wsl/manager.ps1`) fetches the distribution list once per loop iteration, right before drawing the panel and menu. That is fine for commands that finish before the loop continues, but not for **Start distribution** (SC-055): it launches the shell in a new tab and returns immediately, so the re-fetch races `wsl.exe` starting the distribution and usually still reports it as `Stopped`. Nothing refreshes the table after that until the user runs another command. Anything that changes state outside the manager (stopping a distribution from its own shell, `wsl --shutdown` elsewhere, WSL's idle timeout) has the same effect. Observed in the SC-055 UAT on 2026-09-14.

Three ways to keep the table current were considered at filing:

1. **Periodic refresh while the menu is shown.** Not possible with the current TUI: `Read-SpectreSelection` owns the console while it waits, and PwshSpectreConsole's live rendering (`Invoke-SpectreLive`) cannot coexist with it (documented in SC-032). A timer would have to interrupt and redraw the prompt, which the module does not support.
2. **A key press while in the menu.** Same limitation: the selection prompt consumes every key; the only "key" the manager can react to is a chosen entry.
3. **A `Refresh` menu entry.** Fits the existing model: choosing it simply lets the loop iterate, which re-fetches the list and redraws. Cheap, testable, and honest about the mechanism.

**Scope Decisions**:

- **A `Refresh list` menu entry is the mechanism.** It maps to a `refresh` command that does nothing except raise `$script:WslSkipContinuePause`, so the loop redraws immediately without the "Press Enter to continue" pause. Placed as the last entry before `Quit` so it does not push the lifecycle block down.
- **After `Start distribution`, wait briefly before the redraw.** `Invoke-OpenDistroShell` sleeps a short, fixed interval (about one second) after launching so the first redraw already shows `Running` in the common case. This is a best-effort improvement, not a guarantee; `Refresh list` remains the way to be sure. The interval is a constant with a comment, not a parameter.
- **No auto-refresh, no key binding**: ruled out above by the Spectre prompt model. Revisit only together with SC-032.
- **CLI is unaffected**: `list` already fetches fresh data on every call.

**Acceptance Criteria**:
- [ ] `Show-WslMenu` offers `Refresh list` immediately before `Quit`, mapped to `refresh`
- [ ] `Invoke-WslCommand` accepts `refresh`; it fetches nothing itself and raises `$script:WslSkipContinuePause`, so `Start-InteractiveMode` redraws the panel with a freshly fetched list and no pause
- [ ] `Invoke-OpenDistroShell` waits a short fixed interval after launching before returning, so the next redraw usually already shows the started distribution as `Running`
- [ ] Unit tests: menu contains the entry in the right position; `refresh` through `Invoke-WslManager` skips the pause and triggers a second `Get-WslDistroList` fetch on the next iteration; the post-launch wait uses `Start-Sleep` (mocked)
- [ ] `docs/wsl-manager.md` documents the entry and the reason the table can lag
- [ ] All existing tests continue to pass
- [ ] UAT procedure below executed; all steps pass

### UAT Procedure

1. Run `tools\wsl-manager\wsl-manager.bat` with a stopped distribution, select **Start distribution**, pick it. Expected: after the shell tab opens and the menu redraws, the table shows the distribution as `Running` (if it still says `Stopped`, step 2 must fix it).
2. In the distribution's tab run `exit`, wait for WSL to stop it (or run `wsl --terminate <name>` elsewhere), then select **Refresh list**. Expected: the table redraws immediately, no "Press Enter to continue", and shows `Stopped`.
3. Select **Refresh list** twice in a row. Expected: no error, no pause, the table simply redraws.
