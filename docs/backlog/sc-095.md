# [SC-095] setup-dev-stack polish from the SC-066a review

**Status**: Open
**Priority**: Low
**Component**: `lib/wsl/dev-stack.ps1`, `lib/wsl/scripts/setup-dev-stack.sh`, `lib/wsl/ansible/dev-stack.yml`, `tools/wsl-manager/wsl-manager.ps1`, `lib/wsl/dev-stack.Tests.ps1`, `lib/wsl/manager.devstack.Integration.Tests.ps1`
**Related**: [SC-066a](sc-066a.md)

**Summary**:
As a developer, I want the small findings of the SC-066a review fixed, so that `setup-dev-stack` fails early with a clear message and its code says no more than it does.

**Description**:
The closed loop of SC-066a left these Minor findings open; none of them changes what the command installs:

- `-Username` without a default user in the distribution cannot succeed: `Invoke-WslDistroScript` runs the script as the default user, which is then root, and the script refuses root.
- `Install-WslDevStack` writes `wsl.conf` before `ShouldProcess`, as `Install-WslPodman` did; `-WhatIf` still changes `wsl.conf`.
- `Install-WslDevStack` reads `wsl.conf` and the default user more than once.
- `setup-dev-stack.sh` does not check for ansible-core 2.15 or later: on Debian 12 or Ubuntu 22.04 it fails late, with exit 5.
- `setup-dev-stack.sh` does not check for sudo up front: a user without sudo fails at the first privileged step.
- `setup-dev-stack.sh` defines `OLD_DOCKER_LIST` and `OLD_DOCKER_KEY` and then repeats the paths as literals; its comment says it removes only what wsl-manager wrote, but the marker also matches a hand-made list that follows Docker's pre-2023 install docs.
- The DevPod post_task in `dev-stack.yml` skips `provider use docker` when a `docker` provider exists but is not the default, and its guard and test match only the word `docker` in the provider list.
- The `wsl-manager.ps1` help places the `-Username` line for setup-dev-stack above "prompted interactively", which is true only for setup-user.
- The `wsl.conf` boot command `mount --make-rshared /` duplicates the role's `dev-stack-shared-root.service`.
- `manager.devstack.Integration.Tests.ps1` passes the script path to `bash -l` in single quotes inside the `bash -c` string; a repository path with a single quote breaks it.
- The resource probe in `manager.devstack.Integration.Tests.ps1` was added to diagnose [SC-096](sc-096.md); remove it when SC-096 closes.

**Acceptance Criteria**:
- [ ] `setup-dev-stack` with `-Username` and no default user stops with a message before anything changes
- [ ] `-WhatIf` changes nothing, `wsl.conf` included
- [ ] `setup-dev-stack.sh` stops with a clear message when ansible-core is older than 2.15 or the user has no sudo
- [ ] The DevPod step makes `docker` the default provider when it already exists
- [ ] The help, the comments and the old-source marker say what the code does
- [ ] All existing tests continue to pass
