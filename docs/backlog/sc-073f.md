# [SC-073f] C4 elements as needs

**Status**: Open
**Priority**: Medium
**Component**: `docs/architecture/workspace.dsl`, a generator under `tools/structurizr/` (new), `ubproject.toml`
**Depends on**: [SC-073b](sc-073b.md), [SC-073c](sc-073c.md)

**Summary**:
As the maintainer, I want the elements of the C4 model to be needs that link the requirements they realise, so that the architecture is part of the traced model without a second description of it.

**Description**:
The model stays in Structurizr DSL ([SC-062](sc-062.md)); Structurizr local writes it to the committed `docs/architecture/workspace.json`. A generator turns the elements of that file into a `needs.json`, which both readers import with `needimport` (ubCode indexes imported needs, as in useblocks/SPLed). An element names its requirements in a DSL property, so the link is written once, next to the element.

**Scope Decisions**:
- **Source**: `workspace.json`, which is committed, so the generator needs no Structurizr.
- **Generator in PowerShell**, with Pester tests, like the rest of `tools/`.
- **First slice**: the px-proxy container. The other elements become needs as their tools get requirements.
- **Decided in this item**: the need ID scheme for elements, and whether the generated `needs.json` is committed (ubCode needs it present) or built by a task that CI checks.

**Acceptance Criteria**:
- [ ] The px-proxy container is a need that links its requirements, in ubCode and in the Sphinx build
- [ ] The generator has Pester tests and reads only `workspace.json`
- [ ] A changed model with a stale `needs.json` fails CI
