# [SC-015] Reorganize project structure: separate tools from libraries

**Status**: Open
**Priority**: Medium
**Component**: `tools/pslib/`

**Summary**:
As a developer, I want wsl-manager located at `./tools/wsl-manager/` and pslib at `./lib/` so that the project structure clearly separates executable tools from reusable libraries.

**Description**:
Currently, wsl-manager (a tool) lives inside `tools/pslib/wsl/` and pslib (a library) lives inside `tools/pslib/`. This conflates two different concerns: `pslib` is a reusable library (`utils/utils.ps1`), while `wsl-manager` is a standalone tool that depends on that library.

Target structure:
```
lib/
  pslib/
    utils/utils.ps1          # Reusable PowerShell utilities
    AGENTS.md
tools/
  wsl-manager/
    wsl-manager.ps1           # Tool entry point
    wsl-manager.bat           # Batch wrapper
    wsl.ps1                   # WSL library (dot-sources lib/*.ps1)
    lib/                      # WSL-specific modules
    scripts/                  # Shell scripts
    tests/                    # All wsl-manager tests
```

Impact analysis: ~216 path references across ~42 files (source code, docs, skills, backlog items, CI config) need updating. This includes dot-source paths in PowerShell scripts, documentation paths, skill references, and CI pipeline paths.

**Acceptance Criteria**:
- [ ] `tools/pslib/utils/` moved to `lib/pslib/utils/`
- [ ] `tools/pslib/wsl/` moved to `tools/wsl-manager/`
- [ ] All internal dot-source paths updated (e.g., `utils.ps1` sourcing)
- [ ] All documentation paths updated (`docs/wsl-manager.md`, `README.md`, etc.)
- [ ] All skill references updated (`.claude/skills/`)
- [ ] CI pipeline paths updated if applicable
- [ ] Keypirinha/Flow Launcher shortcuts updated
- [ ] `.bat` wrapper paths updated
- [ ] All existing tests continue to pass
