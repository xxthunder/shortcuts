# [SC-056] Escape distribution names before Spectre renders them

**Status**: Open
**Priority**: High
**Component**: `lib/wsl/commands.ps1`, `lib/wsl/commands.Tests.ps1`, `lib/wsl/manager.Tests.ps1`
**Related**: [SC-016c](sc-016c.md) (distro table), [SC-016d](sc-016d.md) (distro pickers), [SC-016e](sc-016e.md) (confirmation prompt, already escaped)

**Summary**:
As a user with a distribution whose name contains square brackets, I want the WSL Manager TUI to show that name literally instead of crashing or colouring it, so that one oddly named distribution cannot make the whole manager unusable.

**Description**:
PwshSpectreConsole renders these as Spectre markup, and the manager passes distribution names into them unescaped:

- `Read-SpectreSelection` choices in `Select-WslDistro` and `Invoke-CreateDistro` (`lib/wsl/commands.ps1`). The wrapper hands the strings straight to `SelectionPrompt.AddChoices` (PwshSpectreConsole 2.6.3, `PwshSpectreConsole.psm1`), and Spectre.Console parses them.
- The `Name` column of `Show-WslDistroTable`, because the table is rendered with `-AllowMarkup` for the coloured `State` and `Default` columns.

Verified on 2026-09-13 in a real console: a choice of `x[bad` throws `Encountered malformed markup tag at position 5`, so every picker in the TUI fails for all distributions as soon as one such name exists; `x[red]y[/]` renders styled instead of literally. `wsl --import` accepts such names. The confirmation prompt had the same defect and was fixed in SC-016e (PR #86) with `Get-SpectreEscapedText`; the prompt message is plain output, so escaping it was a one-liner.

The pickers are not a one-liner: escaping the choice strings changes what `Read-SpectreSelection` returns (`x[[bad` instead of `x[bad`), which would then be handed to the action function as the distribution name.

**Scope Decisions**:

- **Pickers pass objects with `-ChoiceLabelProperty`, not escaped strings.** `Read-SpectreSelection -Choices <objects> -ChoiceLabelProperty { Get-SpectreEscapedText -Text $_.Name }` renders the escaped label and returns the original object, so `.Name` is the exact distribution name. `Select-WslDistro` passes its `$Distros` objects; `Invoke-CreateDistro` wraps its string list in `[PSCustomObject]@{ Name = ... }`; the **Back to main menu** entry becomes an object with that `Name`. The `$WslPickerBackChoice` comparison stays a string comparison on `.Name`.
- **The table escapes only the `Name` column.** `State` and `Default` are markup the code builds itself and stay as they are; `Name` is user data and goes through `Get-SpectreEscapedText`.
- **`Get-SpectreEscapedText` is stubbed in unit tests like the other Spectre commands.** The stub returns its input unchanged; tests assert the escape helper is invoked with the raw name and that the label scriptblock is used, not that brackets are doubled (that is the module's behaviour, not ours). One fixture uses a bracketed name (`Debi[an]`) end to end through `Invoke-WslManager -Command remove` to prove the action receives the raw name.
- **Not in scope**: `Show-WslMenu` (constant labels), the `To start:` hints (plain `Write-Output`), and any input validation of distribution names on import.

**Acceptance Criteria**:
- [ ] `Select-WslDistro` and `Invoke-CreateDistro` call `Read-SpectreSelection` with choice objects and a `-ChoiceLabelProperty` scriptblock that escapes the name via `Get-SpectreEscapedText`
- [ ] Both pickers return the raw distribution name (`.Name` of the chosen object), including for a name that contains brackets
- [ ] **Back to main menu** still works as the last entry and still raises `$script:WslSkipContinuePause`
- [ ] `Show-WslDistroTable` escapes the `Name` column and leaves `State` and `Default` markup unchanged
- [ ] `commands.Tests.ps1` and `manager.Tests.ps1` stub `Get-SpectreEscapedText` and cover: escape helper invoked per choice, raw name returned for a bracketed fixture, back entry, table Name escaping
- [ ] All existing tests continue to pass
- [ ] UAT procedure below executed; all steps pass

### UAT Procedure

1. Create a throwaway distribution with a bracketed name, e.g. `wsl --export <existing> t.tar; wsl --import "probe[x]" C:\wsl\probe t.tar`.
2. Run `tools\wsl-manager\wsl-manager.bat`. Expected: the table lists `probe[x]` literally; no error.
3. Select **Remove distribution**. Expected: the picker opens and lists `probe[x]` literally, with **Back to main menu** last.
4. Pick `probe[x]`, answer `y` to the confirmation. Expected: the confirmation names `probe[x]` literally; `probe[x]` is removed (proves the raw name reached the action).
5. Clean up: `Remove-Item C:\wsl\probe -Recurse; Remove-Item t.tar`.
