# [SC-064] Update WSL itself from wsl-manager

**Status**: Open
**Priority**: Medium
**Component**: `lib/wsl/commands.ps1` (new command), `lib/wsl/manager.ps1`, `tools/wsl-manager/wsl-manager.ps1`, `docs/wsl-manager.md`
**Related**: [SC-063](sc-063.md) (a `wsl --update` to WSL 3.0 broke `setup-docker`)

**Summary**:
As a developer, I want to update WSL itself from wsl-manager and see the version before and after, so that I update WSL on purpose and can tell what changed when something breaks afterwards.

**Description**:
The `update` command updates the packages inside a distribution: `Update-WslDistro` runs `apt update && apt upgrade` in Debian or Ubuntu. No command updates WSL itself. `wsl --update` appears only in `test/bin/init.ps1` for the CI and in the WSL 1 error message in `lib/wsl/core.ps1`.

SC-063 shows why the update should be a deliberate step. `wsl --update` in the CI moved the runner from WSL 2.7.14.0 to 3.0.1.0, and `setup-docker` broke. A user who sees the version change can connect a new failure to it.

Raised on 2026-09-30.

**Scope Decisions**:
- **On request only**: the command runs `wsl --update` when the user chooses it. No other command calls it.
- **Version before and after**: the command shows `wsl --version` before the update and after it.

**Open Questions**:
- **Corporate machines**: IT may manage WSL through the Microsoft Store or Intune. Does `wsl --update` fail there, need admin rights, or is it unwanted? How does the command say so?
- **Taking effect**: does the new version need `wsl --shutdown` before it runs, and should the command offer it, knowing that it stops every running distribution?
- **Way back**: if an update breaks something, as in SC-063, should the command help to go back to a named release?
- **Menu**: where does the command sit in the TUI, given the grouping planned in [SC-031](sc-031.md)?

**Acceptance Criteria**:
- [ ] A command in the TUI and the CLI runs `wsl --update` after a confirmation
- [ ] It shows the WSL version before and after the update, and says when nothing changed
- [ ] A failed update (no rights, managed by IT, no network) ends with a clear message and a non-zero result
- [ ] Unit tests cover an update, no change and a failure with `wsl.exe` faked
- [ ] `docs/wsl-manager.md` describes the command
