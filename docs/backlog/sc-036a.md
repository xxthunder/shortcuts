# [SC-036a] ✅ DONE - Add setup-proxy mode/auth prompts and mode marker

**Status**: Done (2026-04-20)
**Priority**: High
**Component**: `lib/wsl/proxy.ps1`, `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/scripts/setup-proxy-negotiate.sh` (new), `lib/wsl/proxy.Tests.ps1`
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer, I want `setup-proxy` to ask me upfront whether I want Auto, Manual, or Remove — and, when a proxy URL is resolved, whether to use Basic or Negotiate auth — so that the tool's intent is obvious from the first prompt and I can opt into Kerberos mode in later slices.

**Description**:
Foundation slice for the SC-036 epic. Two prompt changes plus a mode marker:

1. **Top-level mode prompt** `[A]uto / [M]anual / [R]emove` replaces the current PAC-first branching in `Install-WslProxy`. Auto runs PAC detection and asks the user to confirm the resolved URL. Manual goes straight to a `host:port` prompt. Remove dispatches `setup-proxy.sh --remove` with no further prompts.
2. **Auth-method prompt** `[B]asic / [N]egotiate`, shown only after a URL is resolved. Negotiate is stubbed in this slice: `Install-WslProxy` dispatches to a new sibling script `setup-proxy-negotiate.sh` which prints "not yet implemented" and exits with code 10.
3. **Mode marker file** `/etc/wsl-manager/proxy-mode` (values `basic` or `negotiate`) so future `--remove` (SC-036e) can tear down the correct set of artifacts without guessing.

Basic mode continues to call `setup-proxy.sh` unchanged, but now also writes `basic` to the marker file so SC-036e's mode-aware teardown works uniformly from day one.

**Scope Decisions**:
- **Upfront A/M/R prompt over PAC-first branching**: makes the tool's intent obvious from the first prompt rather than surfacing different follow-up prompts depending on whether PAC was found. "Remove" also gives users an interactive path to tear down config without needing to remember the `--remove` flag.
- **Auto → DIRECT collapses to Remove**: when PAC resolves to DIRECT, dispatch the same `setup-proxy.sh --remove` teardown that the Remove branch uses. Semantically identical (no proxy applies to this network) and keeps the concept count small.
- **Auto with no PAC errors out**: if the user explicitly picks Auto and no PAC/AutoConfigURL is present in the registry, fail with a hint to re-run and choose Manual. No silent fallback — the user's intent was "figure it out for me", and we can't.
- **Auto confirmation gate**: after PAC resolves to a URL, show it and ask `[Y/N]` before proceeding. Preserves the transparency of the old flow, where the resolved proxy was always printed.
- **`--remove` flag stays**: scripted/non-interactive teardown must not require a TTY. The interactive Remove branch is a convenience over the flag, not a replacement.
- **Sibling script, not branching**: Negotiate logic goes in a new `setup-proxy-negotiate.sh` rather than branching inside `setup-proxy.sh`. Keeps each script single-purpose (the existing script writes config files; the new one also installs packages and starts a service — three different kinds of work).
- **Marker file location**: `/etc/wsl-manager/proxy-mode`. System-wide (setup-proxy already writes root-owned files to `/etc/apt/apt.conf.d/`), survives user-home churn, explicit over auto-detecting by presence of `~/.local/bin/px`.
- **Stub the Negotiate path**: emit "not yet implemented", exit code 10, so later slices land as functional additions rather than behavior changes.
