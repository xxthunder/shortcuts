# [SC-036a] Add auth-method prompt and mode marker to setup-proxy

**Status**: Open
**Priority**: High
**Component**: `lib/wsl/proxy.ps1`, `lib/wsl/scripts/setup-proxy.sh`, `lib/wsl/scripts/setup-proxy-negotiate.sh` (new), `lib/wsl/proxy.Tests.ps1`
**Parent**: [SC-036](sc-036.md)

**Summary**:
As a developer, I want `setup-proxy` to prompt me to choose between Basic and Negotiate auth so that I can opt into the Kerberos-based mode in later slices, while Basic mode remains unchanged.

**Description**:
Foundation slice for the SC-036 umbrella. Adds the auth-method choice to `Install-WslProxy` and introduces a **mode marker file** (`/etc/wsl-manager/proxy-mode`, values `basic` or `negotiate`) so that future `--remove` (SC-036e) can tear down the correct set of artifacts without guessing.

The Negotiate path is stubbed in this slice: `Install-WslProxy` dispatches to a new sibling script `setup-proxy-negotiate.sh` which prints "not yet implemented" and exits non-zero. This keeps the dispatch plumbing complete and testable end-to-end while the actual Negotiate work ships in SC-036b/c/d.

Basic mode continues to call `setup-proxy.sh` unchanged, but now also writes `basic` to the marker file so that SC-036e's mode-aware teardown works uniformly from day one.

**Scope Decisions**:
- **Sibling script, not branching**: Negotiate logic goes in a new `setup-proxy-negotiate.sh` rather than branching inside `setup-proxy.sh`. Keeps each script single-purpose (the existing script writes config files; the new one also installs packages and starts a service — three different kinds of work).
- **Marker file location**: `/etc/wsl-manager/proxy-mode`. System-wide (setup-proxy already writes root-owned files to `/etc/apt/apt.conf.d/`), survives user-home churn, explicit over auto-detecting by presence of `~/.local/bin/px`.
- **Stub the Negotiate path**: emit "not yet implemented", exit code 10, so later slices land as functional additions rather than behavior changes.

**Acceptance Criteria**:
- [ ] `Install-WslProxy` prompts the user to choose auth method: `Basic` or `Negotiate` (only when a proxy URL is resolved; DIRECT path skips the prompt)
- [ ] Basic path dispatches to existing `setup-proxy.sh` unchanged
- [ ] Negotiate path dispatches to new `setup-proxy-negotiate.sh`
- [ ] New `setup-proxy-negotiate.sh` exists, accepts the same base args (`--proxy-url`, `--no-proxy`, `--username`), prints a clear "not yet implemented" message, and exits with code 10
- [ ] Basic mode writes `basic` to `/etc/wsl-manager/proxy-mode` (creates the directory if missing)
- [ ] `--remove` in `setup-proxy.sh` deletes `/etc/wsl-manager/proxy-mode` on successful teardown
- [ ] Pester unit tests cover the auth-method prompt branch (mock the script invocation; assert correct script is called)
- [ ] All existing tests continue to pass
